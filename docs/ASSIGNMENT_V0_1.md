# VEQTA — assignment v0.1

Статус: **рабочая гипотеза, не принятое решение**.

Цель — определить, как использовать штатный Assignment Frappe без дублирования данных и без создания собственного responsibility engine.

## 1. Что уже умеет Frappe

Штатный `Assign To` создаёт связанный `ToDo` для пользователя и ведёт список назначений документа в системном `_assign`.

Если целевой DocType содержит поле `assigned_to`, Frappe при назначении автоматически записывает туда пользователя. При закрытии или снятии assignment Frappe очищает `assigned_to`.

Это важная точка переиспользования Frappe.

## 2. Почему нельзя считать `_assign` аналитическим источником

`_assign` — системное поле Frappe, которое хранит JSON-массив пользователей и предназначено для механизма Assignment/UI.

Для VEQTA это неудобный первичный факт, если нужен однозначный текущий ответственный и нормальные SQL-фильтры.

Поэтому кандидат для `Work Item`:

```text
assigned_to    Link -> User, optional
```

а системный Assignment/ToDo используется как инфраструктурный механизм Frappe.

## 3. Важное ограничение

Frappe Assignment допускает назначение нескольких пользователей, а `assigned_to` — одно Link-поле.

Следовательно, нельзя заранее объявлять штатный `Assign To` единственным источником истины без проверки поведения множественных назначений.

Прототип должен ответить:

1. нужен ли VEQTA вообще multiple assignment;
2. можно ли ограничить пользовательский сценарий одним назначенным;
3. остаются ли `_assign`, ToDo и `assigned_to` согласованными во всех нужных операциях;
4. нужно ли скрыть/ограничить стандартный multi-assign UI;
5. нужен ли минимальный hook для синхронизации.

## 4. Текущая предпочтительная гипотеза

Для v0.1:

- один `assigned_to` как структурированный текущий ответственный;
- поле необязательное;
- не создавать отдельный Responsibility/Ownership DocType;
- максимально использовать стандартный Assignment Frappe;
- не создавать историю назначения до доказанной аналитической необходимости.

## 5. Терминология

Предпочтительное техническое имя поля — `assigned_to`, а не `responsible`.

Причина: Frappe уже имеет специальную поддержку поля с таким именем, поэтому VEQTA может получить штатный Assignment UX с меньшим количеством собственного кода.

Пользовательская подпись может быть локализована как `Ответственный` или `Исполнитель`.

## 6. Что пока не создаём

- Responsibility Engine;
- RACI;
- Team Ownership;
- Role Ownership;
- Participants model;
- отдельную историю назначения;
- собственный Assignment UI.
