# 12. List View и фильтры

`List View` — это экран, где Frappe показывает много документов одного DocType.

Если Form View отвечает на вопрос **«что внутри одной записи?»**, то List View — **«какие записи вообще есть и как быстро найти нужные?»**.

Именно здесь пользователь обычно проводит большую часть повседневной работы: ищет, фильтрует, сортирует, выбирает несколько записей и выполняет массовые действия.

Проверено: **2026-08-30**.

## 1. Самый простой пример

Есть DocType `Request`.

В нём уже накопились документы:

```text
REQ-0001   Проверить отчёт      High     Open
REQ-0002   Подготовить акт      Medium   In Progress
REQ-0003   Исправить данные     High     Open
REQ-0004   Закрыть сверку       Low      Closed
```

Form View показывает один `REQ-0001`.

List View показывает сразу весь набор:

```text
Request

Subject               Priority   Status
-------------------------------------------
Проверить отчёт        High       Open
Подготовить акт        Medium     In Progress
Исправить данные       High       Open
Закрыть сверку         Low        Closed
```

Каждая строка — отдельный Document.

Нажатие на строку открывает его Form View.

## 2. List View Frappe создаёт сам

Для обычного DocType не нужно отдельно писать страницу со списком.

Frappe читает metadata и строит List View автоматически.

Упрощённо:

```text
DocType
  +
DocFields
  +
permissions
     ↓
  List View
```

Официальная документация указывает, что List View создаётся для DocTypes, кроме `Child Table` и `Single`.

Это логично:

- Child Documents обычно показываются внутри родителя;
- Single DocType существует в единственном экземпляре, поэтому список из одного элемента ему не нужен.

## 3. Что обычно видно в строке

Для `Request` список может выглядеть так:

```text
Проверить отчёт   High   01.09.2026   Open
```

Но Frappe не показывает в строке автоматически все 30 полей формы.

Иначе список быстро превратился бы в нечитаемую таблицу шириной в несколько экранов.

Поэтому нужно выбрать только поля, полезные для быстрого просмотра.

Например:

```text
Subject
Priority
Due Date
Status
```

А длинное описание оставить только в Form View.

## 4. `Title Field` и первая колонка

Если у DocType задан `Title Field`, Frappe использует его как основное человекочитаемое значение строки.

Например:

```text
name    = REQ-0001
subject = Проверить отчёт
```

и:

```text
Title Field = subject
```

Тогда пользователь прежде всего видит:

```text
Проверить отчёт
```

а не только технический `REQ-0001`.

Если `Title Field` нет, основой строки становится `name`.

## 5. `In List View`

У DocField есть настройка:

```text
In List View
```

Она говорит Frappe:

> это поле полезно показывать прямо в списке.

Пример:

```text
Subject      In List View ✓
Priority     In List View ✓
Due Date     In List View ✓
Description  In List View ✗
```

В результате пользователь видит главное, а не весь документ целиком.

Это одна из самых простых и полезных настроек интерфейса Frappe.

## 6. Не превращай List View в Excel на 40 колонок

Технически в v16 `List Settings` умеет работать с большим числом полей, но интерфейс списка всё равно рассчитан на быстрый обзор.

Хороший List View отвечает на три вопроса:

```text
что это?
в каком оно состоянии?
что мне нужно знать, прежде чем открыть запись?
```

Для `Request` часто достаточно:

```text
Subject
Priority
Due Date
Status
```

Если для работы нужно анализировать 25 колонок одновременно, вероятно, нужен уже `Report View` или отдельный Report, а не перегруженный List View.

## 7. Фильтр — это условие отбора

Представим 500 заявок, а нам нужны только:

```text
Status = Open
```

Добавляем фильтр, и Frappe показывает только подходящие записи.

Ещё пример:

```text
Priority = High
```

Или несколько условий сразу:

```text
Status   = Open
Priority = High
```

Это означает:

```text
покажи только открытые заявки
с высоким приоритетом
```

## 8. Из чего состоит обычный фильтр

Фильтр удобно читать как простое предложение:

```text
поле + условие + значение
```

Например:

```text
Priority = High
```

где:

```text
Priority  → поле
=         → оператор
High      → значение
```

Другой пример:

```text
Due Date < 2026-09-01
```

То есть:

> срок раньше 1 сентября 2026 года.

Фильтры можно комбинировать.

## 9. `=` и `Like`

Для новичка особенно полезно понимать разницу между двумя частыми вариантами поиска текста.

### Equals

```text
Subject = Проверить отчёт
```

Ищем точное значение.

### Like

```text
Subject like отчёт
```

Ищем текст, содержащий нужный фрагмент.

В v16 у текстовых стандартных фильтров интерфейс позволяет переключать режим `Equals / Like`.

Поэтому не нужно создавать отдельное поле только ради поиска по части текста.

## 10. `In List Filter`

В metadata DocField v16 настройка называется:

```text
In List Filter
```

Техническое поле metadata:

```text
in_standard_filter
```

Если включить эту настройку, поле появляется среди быстрых фильтров прямо над списком.

Например для `Request` удобно сделать быстрыми:

```text
Status
Priority
Department
```

Тогда пользователь не открывает расширенный конструктор фильтров каждый раз.

Условно экран становится таким:

```text
[ ID ] [ Status ] [ Priority ] [ Department ] [Filter]

-------------------------------------------------------
список документов
```

### Что не надо туда добавлять

Не стоит выводить десять редко используемых полей только потому, что это возможно.

Быстрые фильтры должны соответствовать реальной ежедневной работе.

## 11. Полный `Filter`

Если нужного поля нет среди быстрых фильтров, используется обычная кнопка `Filter`.

Там можно собрать более точное условие.

Например:

```text
Department = Analytics
AND
Due Date < 2026-09-01
AND
Status != Closed
```

В данных ничего нового не создаётся.

Мы просто меняем выборку существующих Documents.

Это важная идея:

```text
один DocType
+
разные фильтры
=
разные рабочие выборки
```

Не нужно создавать отдельные DocTypes `Open Request`, `High Priority Request`, `My Request` только ради разных списков.

## 12. Можно фильтровать прямо по значению в строке

В стандартном List View многие значения кликабельны как фильтр.

Например пользователь видит:

```text
Priority: High
```

и нажимает на `High`.

Frappe может добавить:

```text
Priority = High
```

в текущую выборку.

То же особенно удобно для `Link`, `Select`, статуса и некоторых других значений.

Это позволяет быстро сузить список без ручного заполнения Filter dialog.

## 13. Saved Filters

Допустим, каждое утро пользователь собирает одну и ту же выборку:

```text
Status = Open
Priority = High
Department = Analytics
```

Повторять это руками каждый день бессмысленно.

В Frappe 16 есть `Saved Filters`.

Пользователь собирает фильтры один раз и выбирает:

```text
Save Current Filter
```

Например называет его:

```text
Критичные открытые
```

После этого эту выборку можно применять снова одним действием.

Под капотом Frappe хранит её как документ `List Filter`.

В нём есть, среди прочего:

```text
Filter Name
Reference Document Type
For User
Filters
```

## 14. Личный и глобальный Saved Filter

Обычный сохранённый фильтр привязан к пользователю.

Например:

```text
Мои просроченные
```

может быть нужен только одному человеку.

В v16 пользователи с соответствующей системной ролью могут создать глобальный Saved Filter, который не привязан к конкретному `for_user`.

Практически это удобно для общих рабочих выборок вроде:

```text
Просроченные
Требуют проверки
Без исполнителя
```

Но не каждую личную выборку стоит превращать в глобальную.

## 15. Frappe запоминает последнее состояние списка

Есть ещё один механизм, который легко спутать с Saved Filter.

List View сохраняет пользовательские настройки последнего просмотра, включая:

```text
filters
sort_by
sort_order
last_view
```

Поэтому если пользователь отфильтровал список и вернулся к нему позже, Frappe может восстановить его последнее состояние.

Это **не то же самое**, что именованный Saved Filter.

Разница:

```text
последнее состояние
→ Frappe помнит, как ты оставил экран

Saved Filter
→ ты явно сохранил именованную выборку для повторного использования
```

## 16. Сортировка

Фильтр отвечает:

> какие документы показать?

Сортировка отвечает:

> в каком порядке их показать?

Например:

```text
Due Date ASC
```

покажет ближайшие сроки первыми.

А:

```text
creation DESC
```

— сначала новые записи.

В v16 можно сортировать через selector или нажатием на заголовок подходящей колонки.

Повторное нажатие меняет направление:

```text
ASC ↔ DESC
```

## 17. Default Sort Field и Sort Order

На уровне DocType можно задать стандартную сортировку.

Например:

```text
Sort Field = modified
Sort Order = DESC
```

Тогда новый пользователь изначально увидит недавно изменённые записи выше.

Но пользовательская последняя сортировка может затем сохраниться в его настройках List View.

То есть есть разница между:

```text
дефолтом DocType
```

и:

```text
последним выбором конкретного пользователя
```

## 18. List Settings

В Frappe 16 для List View есть отдельный механизм `List Settings`.

Через него системный пользователь с нужными правами может настроить, например:

- состав и порядок колонок;
- показ Tags;
- подсчёт комментариев;
- автоматическое обновление;
- поведение счётчика;
- некоторые настройки для больших списков;
- разрешение bulk edit при Workflow.

Для новичка самое полезное здесь — настройка колонок.

Можно добавить нужные поля, убрать лишние и переставить их без написания собственного List View.

## 19. `In List View` и `List Settings` — не одно и то же

Это два уровня настройки.

### `In List View`

Свойство самого DocField:

```text
Priority → In List View ✓
```

Это базовая metadata модели.

### `List Settings`

Дополнительная настройка конкретного List View:

```text
какие поля показать
в каком порядке
```

Поэтому сначала разумно настроить нормальную metadata DocType, а уже потом доводить список через List Settings.

## 20. Количество строк и `Load More`

Frappe не обязан загружать все 100 000 документов сразу.

В текущем v16 List View предусмотрены размеры выборки:

```text
20
100
500
2500
```

и действие:

```text
Load More
```

Это обычная пагинация/дозагрузка данных.

Если список огромный, не нужно ожидать, что браузер превратится в Excel и сразу загрузит всю таблицу.

Для большой выгрузки есть Export и отчёты.

## 21. Что происходит при выборе нескольких строк

Слева у строк есть checkbox.

Например выбираем:

```text
☑ REQ-0001
☑ REQ-0003
☑ REQ-0014
```

После этого Frappe показывает `Actions` для выбранных документов.

Набор действий зависит от DocType и прав пользователя.

В v16 штатный List View умеет, среди прочего:

```text
Edit
Export
Assign To
Clear Assignment
Apply Assignment Rule
Add Tags
Print
Submit
Cancel
Delete
Copy to Clipboard
Workflow actions
```

Не все пункты будут доступны всегда.

Например `Submit` имеет смысл только для Submittable DocType и при наличии соответствующего permission.

## 22. Bulk Edit

Если нужно у десяти документов поставить:

```text
Priority = High
```

не обязательно открывать каждый Form View отдельно.

При подходящих условиях можно выбрать записи и выполнить:

```text
Actions → Edit
```

Это массовое изменение полей.

Но использовать его нужно осмысленно: Frappe всё равно работает с реальными Documents и их правилами, а не просто красит ячейки таблицы.

При наличии Workflow bulk editing может дополнительно зависеть от `List Settings → Allow Bulk Editing`.

## 23. Assignment прямо из списка

Можно выбрать несколько документов и выполнить:

```text
Assign To
```

Например:

```text
REQ-0001
REQ-0003
REQ-0007
        ↓
Assign To → user@example.com
```

Это штатный механизм Assignment, а не отдельное поле `executor`, которое List View сам придумал.

Позже Assignment и ToDo будут разобраны отдельной главой.

## 24. Permissions всё равно действуют

List View — не обход системы прав.

Если у пользователя нет `read` для DocType, список не должен открываться.

Кроме общих permissions, на итоговый набор Documents могут влиять User Permissions и другие ограничения доступа.

Поэтому два пользователя могут открыть один и тот же DocType и увидеть разный набор записей.

Это нормально.

Пример:

```text
User A → 120 Requests
User B → 34 Requests
```

не обязательно означает ошибку List View.

Возможно, у них разные разрешения на данные.

## 25. Tags, Assignments, comments и служебная информация

Строка List View может показывать не только DocFields.

В стандартном интерфейсе могут присутствовать:

```text
Tags
назначенные пользователи
дата последнего изменения
comment count
like
status indicator
```

Это системная информация вокруг Document.

Не нужно создавать отдельные поля вроде:

```text
comments_count
assigned_users_text
```

только ради отображения того, что Framework уже умеет показывать сам.

## 26. Переключение на другие Views

Те же Documents можно смотреть не только списком.

В зависимости от DocType и настройки v16 поддерживает переключение между представлениями вроде:

```text
List
Report
Dashboard
Calendar
Gantt
Kanban
Image
Tree
Map
```

Доступность конкретного View зависит от данных и metadata.

Например Calendar бессмысленен без подходящей календарной настройки, а Tree нужен иерархическому DocType.

Главная мысль:

```text
Documents остаются теми же
меняется способ их просмотра
```

## 27. Фильтры переходят между Views

В v16 при переключении представлений Frappe умеет переносить текущие search parameters / filters.

Например:

```text
Status = Open
Priority = High
```

сначала смотрим как List, затем переключаемся на Kanban.

Мы не создаём новую базу заявок для Kanban — меняется только представление той же выборки.

## 28. Когда хватает штатного List View

В большинстве внутренних CRUD-сценариев штатного списка достаточно, если нужно:

```text
просмотреть документы
отфильтровать
отсортировать
открыть запись
выбрать несколько записей
выполнить массовое действие
перейти в другой View
```

Сначала стоит настроить:

```text
Title Field
In List View
In List Filter
Sort Field / Sort Order
List Settings
Saved Filters
```

И только потом решать, что стандартный интерфейс «не подходит».

## 29. Когда появляется код

Если стандартного поведения уже недостаточно, Frappe позволяет кастомизировать List View.

Для Standard DocType в App используется файл вида:

```text
{doctype}_list.js
```

Например:

```text
request_list.js
```

Через него можно добавлять:

- дополнительные поля для загрузки;
- default filters;
- formatters;
- row buttons;
- свои действия;
- дополнительное поведение List View.

Для site-specific логики документация также допускает Client Script типа `List`.

Но для новичка правильный порядок такой:

```text
metadata
    ↓
List Settings / filters
    ↓
Saved Filters
    ↓
и только затем List JS / Client Script
```

## 30. Маленький пример настройки `Request`

Пусть есть поля:

```text
subject
status
priority
department
due_date
description
```

Для удобной ежедневной работы можно начать так:

```text
Title Field = subject

In List View:
✓ priority
✓ due_date
✓ status

In List Filter:
✓ status
✓ priority
✓ department
```

Тогда пользователь получает понятный рабочий экран:

```text
[ID] [Status] [Priority] [Department] [Filter]

Subject              Priority   Due Date     Status
----------------------------------------------------
Проверить отчёт       High       01.09.2026   Open
Подготовить акт       Medium     03.09.2026   In Progress
```

А затем может сохранить выборку:

```text
Status = Open
Priority = High
```

как:

```text
Критичные открытые
```

Без единой строки собственного frontend-кода.

## Мини-практика

На учебном DocType `Request`:

1. Создай 8–10 документов с разными `Status`, `Priority` и `Department`.
2. Для `Priority`, `Due Date` и `Status` включи `In List View`.
3. Для `Status`, `Priority` и `Department` включи `In List Filter`.
4. Открой List View и посмотри, какие колонки появились.
5. Отфильтруй:

   ```text
   Status = Open
   Priority = High
   ```

6. Сохрани эту выборку как Saved Filter.
7. Измени сортировку на `Due Date ASC`.
8. Выбери две записи checkbox-ами и посмотри, какие `Actions` доступны именно с твоими permissions.
9. Переключись в Report View и проверь, сохранилась ли текущая логика фильтрации.

Цель упражнения — почувствовать, что один DocType может обслуживать много рабочих сценариев без создания новых сущностей.

## Что запомнить

1. **List View — штатный список Documents одного DocType.**
2. **`In List View` определяет полезные поля для строк списка.**
3. **`In List Filter` выводит поле в быстрые фильтры.**
4. **Фильтр меняет выборку, а сортировка — порядок.**
5. **Saved Filter — именованная повторно используемая выборка.**
6. **Frappe отдельно запоминает последнее состояние списка конкретного пользователя.**
7. **Массовые действия уже встроены и зависят от DocType и permissions.**
8. **List, Kanban, Calendar и другие Views могут показывать одни и те же Documents по-разному.**
9. **Код List View нужен только после того, как исчерпаны metadata и штатные настройки.**
