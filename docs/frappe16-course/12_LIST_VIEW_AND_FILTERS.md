# 12. List View, фильтры и сортировка

В главе 11 мы привели в порядок Form View одного `Request`.

Теперь переходим на следующий штатный экран Frappe — `List View`: здесь пользователь работает уже не с одной записью, а с набором Documents одного DocType.

Проверено для **Frappe Framework v16.32.0**.

---

## Что уже есть на стенде

`Request` имеет рабочую двухвкладочную форму и реальные Documents.

Для списка особенно важны уже существующие поля:

```text
Subject
Status
Priority
Due Date
Responsible
```

Из блока B у нас уже включено:

```text
Status   → In List View
Priority → In List View
Due Date → In List View
```

В этой главе мы добавим быстрые фильтры для `Status` и `Priority` и создадим небольшой детерминированный набор данных для упражнений.

---

## Что такое List View

`List View` показывает много Documents одного DocType.

```text
Request
├── Request A
├── Request B
├── Request C
└── ...
```

Каждая строка относится к отдельному Document.

Клик по строке открывает его Form View.

Frappe строит базовый List View автоматически. Для обычного DocType не нужно отдельно писать свою страницу списка.

---

## Один DocType — много рабочих выборок

Представь 200 Requests.

Сегодня нужны только:

```text
Status = Open
```

Завтра:

```text
Priority = High
```

А руководителю:

```text
Status = Open
AND
Priority = High
```

Для этого не создают отдельные DocTypes вроде:

```text
Open Request
High Priority Request
```

Используется один `Request`, а List View меняет выборку фильтрами.

---

## `In List View`

Свойство DocField:

```text
In List View
```

отвечает за то, какие поля полезно видеть прямо в строках списка.

Для нашего курса оставляем:

```text
Status
Priority
Due Date
```

`Description`, `Notes`, `Items` в список не выводим: длинные и сложные данные удобнее смотреть в Form View.

Разница:

```text
In List View
→ какие сведения показывать у строки

Filter
→ какие Documents вообще попадут в список
```

---

## `In List Filter`

В metadata `DocField` v16.32.0 настройка интерфейса называется:

```text
In List Filter
```

Её техническое поле:

```text
in_standard_filter
```

Она делает поле доступным как быстрый фильтр списка.

В лабораторной включим:

```text
Status   → In List Filter
Priority → In List Filter
```

Это подтверждается metadata `DocField` самой версии v16.32.0.

---

## Фильтр читается как простое условие

Обычный фильтр состоит из:

```text
поле + оператор + значение
```

Например:

```text
Status = Open
```

или:

```text
Priority != Low
```

или:

```text
Due Date < 2026-09-05
```

Несколько условий обычно соединяются как `AND`:

```text
Status = Open
AND Priority = High
```

То есть Document должен удовлетворять обоим условиям.

---

## Текстовый `Like`

Для текстового поля иногда нужно искать не точное значение, а фрагмент.

В нашей лаборатории специально создадим Requests, чьи Subjects начинаются с:

```text
C12-
```

Тогда фильтр по `Subject` через оператор `Like` позволит отделить учебный набор главы 12 от Requests, созданных раньше.

Это важный приём для воспроизводимой практики: результат не зависит от того, сколько других записей накопилось на Site.

---

## Сортировка не меняет выборку

Фильтр отвечает:

```text
что показать?
```

Сортировка отвечает:

```text
в каком порядке показать?
```

Например:

```text
Due Date ASC
```

означает — ближайшие даты выше.

А:

```text
Due Date DESC
```

— поздние даты выше.

Documents при этом не переписываются. Меняется только порядок представления списка.

---

## Почему для обучения нужен фиксированный набор данных

Если просто сказать:

> Создай несколько Request и посмотри фильтры,

результат у каждого ученика будет разный.

Поэтому лабораторная 12 создаст ровно шесть записей:

```text
C12-Open-High-1
C12-Open-High-2
C12-Open-Medium
C12-Progress-High
C12-Progress-Low
C12-Done-High
```

У них заранее заданы Status, Priority, Due Date и Responsible.

После этого мы сможем заранее знать результаты запросов:

```text
C12 + Open + High
→ 2 Documents

C12 + Status != Done
→ 5 Documents

C12 + Done + Low
→ 0 Documents
```

Так фильтрация превращается в проверяемый опыт, а не в «посмотри, что получится».

---

## Пустой список — нормальный результат

Если фильтр не находит ни одной записи, List View показывает пустую выборку.

Это не означает:

```text
DocType сломан
данные удалены
Site упал
```

Это означает только:

```text
ни один Document не удовлетворяет текущим условиям
```

В лабораторной мы специально получим такой результат и затем уберём противоречивое условие.

---

## Фильтры не являются permissions

Очень важно не путать:

```text
Filter
→ пользователь просит показать часть доступных ему Documents

Permissions
→ Framework решает, какие Documents пользователь вообще имеет право читать или изменять
```

В блоке C мы работаем как `Administrator`, поэтому не изучаем ограничения доступа.

Роли и permissions начнутся с главы 17.

---

## List View не заменяет Report

List View хорош для ежедневной операционной работы:

```text
найти
отфильтровать
отсортировать
открыть
выбрать несколько документов
```

Если нужны десятки колонок, группировки, расчёты и аналитика, позже появятся Reports.

Не нужно превращать List View в огромный Excel только потому, что он показывает строки.

---

## Saved Filters и пользовательские настройки

Frappe умеет сохранять пользовательские фильтры и состояние списка.

Это полезно в реальной работе, но в обязательной практике главы 12 мы не будем создавать дополнительную постоянную сущность только ради демонстрации.

Сначала важно руками понять три независимые вещи:

```text
columns
filters
sort
```

К сохранённым рабочим представлениям можно вернуться после первого прохода курса.

---

## Массовые действия

List View позволяет выбирать несколько строк и выполнять доступные действия над выбранными Documents.

Конкретный набор действий зависит от:

```text
DocType
состояния Documents
permissions пользователя
настроек списка
```

В этой главе достаточно увидеть сам механизм выбора нескольких строк. Permission-поведение будем проверять только после создания ограниченных пользователей.

---

## Что произойдёт в лабораторной

Ты:

1. включишь `In List Filter` для `Status` и `Priority`;
2. создашь ровно шесть Requests с префиксом `C12-`;
3. проверишь несколько фильтров с заранее известным количеством результатов;
4. отсортируешь учебный набор по `Due Date`;
5. намеренно задашь комбинацию, которая возвращает 0 строк;
6. очистишь фильтры и оставишь данные для следующих глав.

---

## Что запомнить

1. `List View` показывает много Documents одного DocType.
2. `In List View` определяет полезные поля строки.
3. `In List Filter` добавляет быстрый фильтр.
4. Filter определяет набор Documents, Sort — их порядок.
5. Пустая выборка не означает потерю данных.
6. Фильтр не является механизмом безопасности.
7. Для сложной аналитики позже используются Reports, а не бесконечное расширение List View.
