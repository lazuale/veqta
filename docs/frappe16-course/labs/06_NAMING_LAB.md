# Лабораторная 06. Naming и системное поле `name`

## Что уже должно быть готово

Лабораторная 05 завершена.

`Request` существует и уже содержит:

```text
subject
description
status
due_date
priority
is_urgent
estimate_hours
notes
reference_file
```

`Title Field`:

```text
subject
```

`Auto Name` ещё не настроен.

Есть несколько сохранённых Requests из предыдущих лабораторных.

---

## Что сейчас получим

Для **новых** Request Documents будет действовать:

```text
Auto Name = REQ-.YYYY.-.#####
```

На свежем стенде курса в 2026 году новые записи должны идти как:

```text
REQ-2026-00001
REQ-2026-00002
REQ-2026-00003
...
```

Старые Requests не переименовываем.

---

## Сделай руками

### 1. Посмотри `name` существующего Request

Открой `Request` List View.

Открой любой Document, созданный в лабораторных 04–05.

Зафиксируй два разных значения:

```text
системный name
Subject
```

`Subject` — понятный заголовок.

`name` — системный идентификатор записи.

Запиши или запомни текущий `name` этого Document: он понадобится для сравнения после изменения Subject.

---

### 2. Открой DocType `Request`

Через поиск Desk:

```text
DocType
→ Request
```

Перейди к секции Naming.

В поле:

```text
Auto Name
```

введи точно:

```text
REQ-.YYYY.-.#####
```

Сохрани DocType.

---

### 3. Создай первый Request новой серии

Открой новый `Request` и заполни:

```text
Subject:  Проверить naming 1
Status:   Open
Priority: Medium
Due Date: 2026-09-07
```

Сохрани.

На свежем стенде ожидается:

```text
REQ-2026-00001
```

---

### 4. Создай ещё два Request

Создай:

```text
Subject:  Проверить naming 2
Status:   In Progress
Priority: High
Due Date: 2026-09-08
```

и:

```text
Subject:  Проверить naming 3
Status:   Done
Priority: Low
Due Date: 2026-09-09
```

На чистой последовательности ожидаются:

```text
REQ-2026-00002
REQ-2026-00003
```

Главное наблюдение:

```text
один Auto Name
→ разные уникальные names
→ счётчик увеличивается автоматически
```

---

## Проверь различие `name` и `Subject`

Открой:

```text
REQ-2026-00001
```

Запомни его `name`.

Измени:

```text
Subject: Проверить naming 1
```

на:

```text
Subject: Проверить naming после изменения темы
```

Сохрани.

Ожидаемый результат:

```text
Subject изменился
name остался REQ-2026-00001
```

Это и есть практическая разница между системной идентичностью и Title Field.

---

## Эксперимент

Открой один старый Request, который был создан **до** настройки series.

Сохрани его без Rename.

Ожидаем:

```text
старый name не превращается автоматически в REQ-...
```

Изменение Auto Name не является массовым Rename старых Documents.

---

## Намеренная ошибка — неправильная naming series

Теперь получим гарантированную ошибку синтаксиса серии.

Открой DocType `Request` и временно замени:

```text
REQ-.YYYY.-.#####
```

на:

```text
REQ-#####
```

Сохрани DocType.

После этого создай новый Request:

```text
Subject:  Ошибка naming series
Status:   Open
Priority: Medium
Due Date: 2026-09-10
```

Нажми Save.

Ожидаемый результат:

```text
Document не сохраняется
→ Frappe сообщает об invalid naming series
→ причина: числовой placeholder ##### оформлен без требуемого разделения серии
```

В `v16.32.0` проверка naming series требует корректного формата с точкой перед числовой частью.

---

## Восстановление

Вернись в DocType `Request`.

Восстанови точное значение:

```text
Auto Name = REQ-.YYYY.-.#####
```

Сохрани DocType.

Вернись к несохранённому Request с Subject:

```text
Ошибка naming series
```

Снова нажми Save.

Теперь Document должен успешно получить следующий номер серии, например на чистом стенде:

```text
REQ-2026-00004
```

Если ошибка произошла до получения номера, счётчик останется последовательным.

---

## Проверь итог

В `Request` List View должны одновременно существовать:

```text
старые Documents с именами до настройки series
+
новые Documents REQ-2026-.....
```

Это нормальное состояние курса: мы наблюдали реальный переход стратегии naming, а не переписали историю так, будто серия существовала всегда.

## Состояние стенда после лабораторной

`Request` сохраняет все поля лабораторной 05.

Дополнительно теперь постоянно настроено:

```text
Title Field: subject
Auto Name:   REQ-.YYYY.-.#####
```

Есть:

```text
старые Request Documents, созданные до series
минимум 4 Request Documents с series REQ-2026-.....
```

Неправильная series `REQ-#####` полностью удалена из настройки.

Это точное входное состояние [**главы 07**](../07_LINKS_AND_FETCH.md).
