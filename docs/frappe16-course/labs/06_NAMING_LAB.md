# Лабораторная 06. Naming и системное `name`

## Цель

Увидеть разницу между системным ID Document и человеческим заголовком.

## Сделай руками

1. Открой несколько существующих Request.
2. Сравни в URL/форме:
   - `name`;
   - `Subject`;
   - Title Field.
3. В DocType `Request` настрой naming series, например:

```text
REQ-.YYYY.-.#####
```

4. Создай ещё 2–3 Request.

## Ожидаемый результат

Новые Documents получают системные ID вида:

```text
REQ-2026-00001
```

При этом заголовком формы может оставаться содержимое `Subject`.

## Эксперимент

Измени `Subject` у одного Request после сохранения.

Проверь:

```text
Subject изменился
name не изменился
```

## Намеренная ошибка

Попробуй создать два документа с логикой naming, которая могла бы дать одинаковое имя, либо вручную использовать уже существующий name там, где интерфейс это допускает.

Ожидаемый смысл ошибки: `name` должен быть уникальным ключом Document.

## Проверка себя

Почему Link обычно хранит `name` связанного Document, даже если человеку в UI показывается Title Field?

## Состояние после лабораторной

Оставь стабильную series `REQ-.YYYY.-.#####` для новых Request.
