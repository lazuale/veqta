# Лабораторная 16. Desk Page и границы штатного UI

## Цель

Научиться различать: что собирается metadata, что можно добавить Client Script, а что уже требует собственного Page/App code.

## Сделай руками

В Desk открой и сравни:

```text
Request Form
Request List
Training Workspace
DocType List
User Form
System Console/Page, если доступно роли Administrator
```

Для каждого экрана ответь:

```text
это Form/List/Workspace/Page?
какой объект задаёт его структуру?
```

## Практический тест границ

Возьми три требования:

1. `Due Date` скрывать, если Status = Done.
2. Добавить кнопку `Mark Urgent` на Request Form.
3. Создать отдельный полноэкранный интерфейс с собственной компоновкой, несколькими несвязанными источниками данных и нестандартными контролами.

Для каждого запиши минимальный уровень решения:

```text
metadata / Client Script / Page-App code
```

## Эксперимент

В Form metadata попробуй решить требование №1 через `Depends On`/`Display Depends On`, если условие выражается штатно. Убедись, что отдельный Page для этого не нужен.

## Намеренная ошибка

Попробуй мыслительно решить требование №3 одним Customize Form. Зафиксируй, чего именно не хватает: отдельного route, собственного layout, client controller, server methods и т.д.

## Проверка себя

Объясни, почему «можно написать JS» не означает «для любой задачи нужен свой frontend».

## Состояние после лабораторной

Стенд не меняется, кроме возможного разумного Depends On на учебном поле.
