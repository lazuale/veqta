# Лабораторная 30. Version и Track Changes

## Цель

Увидеть, что Track Changes создаёт структурированную историю изменений, а не просто текстовый лог.

## Подготовка

У `Request` уже должен быть включён `Track Changes`.

## Сделай руками

На одном Request выполни последовательно:

1. `Priority: Medium → High`, Save.
2. `Due Date` изменить, Save.
3. `Description` изменить, Save.
4. добавить/изменить строку Child Table, Save.

После каждого Save смотри Timeline/Versions.

## Проверь `Version`

Через Awesome Bar открой `Version` и найди записи для данного Request.

Посмотри:

```text
docname/ref_doctype
owner
creation
data/change payload
```

Названия полей могут различаться — цель увидеть фактическую структуру текущего v16.

## Эксперимент

Выключи Track Changes у отдельного экспериментального DocType, измени Document несколько раз и сравни наличие Version. Затем верни/оставь настройку осмысленно.

## Намеренная ошибка

Не путай Version с backup. Удали/измени тестовый документ и подумай: Version хранит историю изменений, но не является полноценной стратегией восстановления всей базы.

## Проверка себя

Объясни разницу:

```text
Timeline → пользовательское представление событий
Version  → структурированная запись изменений
Backup   → восстановление данных Site
```

## Состояние после лабораторной

Track Changes у Request оставить включённым.
