## Сделай руками

### 1. Войди в Desk

Открой:

```text
http://learn.localhost:8000
```

Войди как:

```text
Administrator
```

Если ты уже вошёл, повторно авторизовываться не нужно.

---

### 2. Осмотрись на стартовом экране

Найди глазами:

```text
Sidebar
область текущей страницы
переход к Desktop / Workspaces
поиск Desk
пользовательское меню
```

Названия отдельных кнопок могут зависеть от ширины окна и языка интерфейса. Не меняй настройки ради совпадения с картинкой — сейчас важны сами области интерфейса.

---

### 3. Найди `User` через поиск Desk

Открой глобальный поиск и введи:

```text
User
```

Перейди к списку `User`.

Посмотри на адрес браузера. Для списка DocType `User` route должен быть вида:

```text
/app/user
```

Перед тобой:

```text
DocType: User
View:    List View
```

---

### 4. Открой один Document

В списке `User` открой:

```text
Administrator
```

Теперь перед тобой:

```text
DocType:  User
Document: Administrator
View:     Form View
```

Снова посмотри на адрес браузера.

Он изменился: route формы содержит переход к конкретному Document.

Не нужно запоминать URL целиком. Зафиксируй только причинно-следственную связь:

```text
List View
→ один route

Form View
→ другой route
```

---

### 5. Вернись в List View

Вернись к списку `User` штатной навигацией браузера или Desk.

Убедись, что снова видишь несколько Documents.

---

### 6. Через поиск открой ещё четыре системных объекта

Последовательно найди:

```text
DocType
Role
Workspace
System Settings
```

Для каждого остановись на несколько секунд и определи, что перед тобой:

```text
List View
или
Form View
```

Подсказка: `System Settings` — Single DocType, поэтому его поведение отличается от обычного списка множества Documents. Подробно Single DocType будет изучаться позже; сейчас достаточно заметить отличие, не разбирая механизм.

---

### 7. Открой существующий Workspace

Вернись к Desktop или используй Sidebar.

Открой любой уже существующий публичный Workspace Framework, доступный `Administrator`.

Не редактируй его.

Сейчас важно увидеть:

```text
Workspace
≠ List View
≠ Form View
```

Workspace собирает элементы навигации и информации на одной рабочей странице.

---

## Проверь результат

Ты должен уметь повторить без подсказки:

```text
поиск → User → List View
List View → Administrator → Form View
Form View → назад → List View
Sidebar/Desktop → существующий Workspace
```

И на каждом шаге назвать тип экрана.

## Эксперимент

Выбери `Role`.

### Вариант A — через поиск

Найди `Role` глобальным поиском и открой список.

### Вариант B — через навигацию

Вернись на Desktop/Workspace и попробуй добраться до системной области через доступную навигацию Desk, не используя поиск.

Сравни два способа.

Результат должен быть один: ты работаешь с тем же системным объектом, меняется только путь навигации к нему.

Ничего не сохраняй и не редактируй.

## Намеренная ошибка

В адресной строке браузера вручную открой заведомо несуществующий route:

```text
http://learn.localhost:8000/app/training-unicorn-does-not-exist
```

Ожидаемое поведение:

```text
Desk не открывает корректный Workspace, List View или Form View
→ появляется экран/сообщение о том, что route или страница не найдены
```

Точный текст сообщения может зависеть от сборки интерфейса, но правильный результат — **несуществующий route не превращается в новый объект Frappe**.

Никакие данные Site этим действием не изменяются.

## Восстановление

Вернись на рабочий route:

```text
http://learn.localhost:8000/app
```

Затем через поиск снова открой:

```text
User
```

и `Administrator`.

Если List View и Form View открываются как раньше, стенд восстановлен: фактически мы исправили только адрес в браузере.
