# 06. Naming и системное поле `name`

У каждого обычного Document во Frappe есть системный идентификатор `name`.

Это не обязательно «номер документа» и не обязательно текст, который человек видит крупным заголовком. Это **уникальный адрес записи внутри её DocType**.

Проверено: **2026-08-30**.

## 1. `name` на простом примере

Есть DocType:

```text
Request
```

И одна запись:

```text
name = REQ-00042
subject = Проверить отчёт
```

В Python мы можем получить именно эту запись так:

```python
frappe.get_doc("Request", "REQ-00042")
```

В REST API та же идея выглядит так:

```text
/api/resource/Request/REQ-00042
```

То есть пара:

```text
DocType + name
```

однозначно указывает на Document.

## 2. `name` и красивый заголовок — разные вещи

Очень полезно разделять технический ID и подпись для человека.

Например:

```text
name    = REQ-00042
subject = Проверить отчёт за август
```

Если в DocType задать:

```text
Title Field = subject
```

пользователь сможет видеть понятный заголовок, а система продолжит использовать стабильный `REQ-00042`.

Простая аналогия:

```text
name        → номер паспорта записи
Title Field → имя, которое удобно читать человеку
```

Аналогия условная, но смысл передаёт: название может меняться, а идентичность записи лучше держать стабильной.

## 3. Когда человеческое значение можно использовать как `name`

Для небольших стабильных справочников это иногда удобно.

Например:

```text
Currency
name = EUR
```

или:

```text
Country
name = Netherlands
```

Плохой кандидат:

```text
Employee
name = Иван Иванов
```

Почему:

- люди могут иметь одинаковые имена;
- ФИО может измениться;
- могут появиться разные написания;
- интеграции обычно любят стабильные ID.

Если сомневаешься, лучше отделить `name` от отображаемого title.

## 4. Штатные способы Naming в Frappe 16

У DocType есть несколько готовых вариантов. Не нужно сразу писать свой генератор.

| Метод | Что получается | Когда удобно |
|---|---|---|
| **Set by user** | пользователь вводит ID | коды справочника |
| **Autoincrement** | `1`, `2`, `3` | простой числовой ID |
| **By fieldname** | `name` берётся из поля | естественный уникальный код |
| **Naming Series** | `REQ-00001` | документы с сериями |
| **Expression** | ID собирается из шаблона | составные имена |
| **Expression (old style)** | старый формат выражений | совместимость |
| **Random** | случайная строка | внутренние ID |
| **UUID** | UUID | машинный стабильный ID |
| **By script** | имя задаёт код | нестандартная логика |

Разберём их без лишней математики.

## 5. Set by user

Пользователь сам задаёт `name`.

Например:

```text
Warehouse
name = MAIN
```

Хорошо работает, если код короткий, понятный и действительно уникальный.

Если человек каждый раз должен придумывать очередной номер заявки, этот режим уже неудобен.

## 6. Autoincrement

Frappe выдаёт числа:

```text
1
2
3
4
```

Подходит, когда человекочитаемый префикс не нужен.

Не стоит воспринимать такую последовательность как юридически гарантированную «без дыр». Технические идентификаторы и регламентная нумерация документов — не всегда одна и та же задача.

## 7. By fieldname

Можно сказать Frappe: используй значение конкретного поля как `name`.

Например:

```text
DocType: Equipment
Field: equipment_code
Value: EXC-017

name = EXC-017
```

Это удобно, если `equipment_code` уже является настоящим уникальным ID предметной области.

Если значение может измениться — подумай дважды, потому что изменение `name` означает Rename документа.

## 8. Naming Series

Самый знакомый вид:

```text
REQ-00001
REQ-00002
REQ-00003
```

У документа обычно есть поле `naming_series`, а шаблон определяет префикс и счётчик.

Пример идеи:

```text
REQ-.#####
```

где решётки задают числовую часть.

Naming Series удобна, когда пользователю нужен читаемый номер и возможно несколько серий.

Например:

```text
REQ-.#####
INC-.#####
```

Подробный синтаксис лучше проверять по документации конкретной версии, а не пытаться запомнить все варианты сразу.

## 9. Expression

Expression позволяет собрать `name` из значений документа и шаблона.

Условный пример идеи:

```text
{department}-{year}-{####}
```

Результат может выглядеть так:

```text
OPS-2026-0042
```

Используй Expression, когда имя действительно должно отражать несколько частей данных.

Не превращай `name` в мини-базу данных. Если в ID зашито пять изменяемых бизнес-признаков, Rename быстро станет болью.

## 10. Expression (old style)

В Frappe сохранилась поддержка старого формата выражений для совместимости.

Для нового проекта ориентируйся на современный `Expression`, если нет причины использовать legacy-синтаксис.

## 11. Random

Frappe может сгенерировать случайный идентификатор.

Подходит, когда человеку не нужно читать или диктовать ID.

Пример:

```text
k9f3x7q2
```

Точный формат зависит от реализации Framework.

## 12. UUID

UUID удобен для машинных идентификаторов и распределённых интеграций.

Пример:

```text
0198...-....
```

### Нюанс именно v16

Документация Naming всё ещё может описывать UUID как UUID v4, но фактический код ветки `version-16` использует `uuid7()` для этого режима.

Для изучения поведения конкретной версии здесь ориентируемся на исходный код v16.

Новичку достаточно запомнить смысл: **UUID — системный уникальный ID, который обычно не предназначен для ручного ввода человеком**.

## 13. By script

Если штатных схем недостаточно, имя можно назначить кодом в controller через naming lifecycle.

Пример задачи:

```text
ID зависит от внешней системы
или
нужно сложное правило, которое не выражается стандартным шаблоном
```

Этот вариант стоит брать последним, а не первым: standard naming легче сопровождать.

## 14. Document Naming Rule

`Document Naming Rule` позволяет задавать правила именования по условиям.

Пример идеи:

```text
если department = Operations
→ серия OPS-#####

если department = Finance
→ серия FIN-#####
```

Это полезно, когда один DocType должен получать разные серии в зависимости от данных документа.

Правила имеют условия и приоритет, поэтому их нужно проектировать так, чтобы не возникало неоднозначности.

## 15. Что происходит при создании нового Document

Упрощённо Framework делает примерно следующее:

```text
создаётся новый Document
        ↓
срабатывает naming lifecycle
        ↓
выбирается настроенный Naming Method
        ↓
получается уникальный name
        ↓
Document сохраняется
```

До naming можно влиять на данные через соответствующие controller hooks, а при `By script` имя задаёт код.

Точные внутренние функции полезны разработчику позже. На первом проходе важен порядок.

## 16. Rename — изменение `name`

Если поменялось обычное поле `subject`, это обычный Save.

Если меняется:

```text
REQ-00042 → REQ-00105
```

это уже `Rename`.

Frappe имеет штатный механизм Rename, который умеет обновлять известные Link/Dynamic Link references и связанные системные записи.

Именно поэтому нельзя безопасно «переименовать» запись простым SQL UPDATE поля `name`.

## 17. Allow Rename

Для DocType можно разрешать или ограничивать Rename через настройки и permissions.

Сам факт, что Rename технически возможен, не означает, что пользователю нужно давать эту кнопку для любого документа.

Например, справочник с ошибочно введённым кодом иногда разумно переименовать. Подтверждённый транзакционный документ с номером, ушедшим во внешнюю систему, может требовать совсем другой процедуры.

## 18. Почему naming важен для интеграций

Представим внешнюю систему, которая запомнила:

```text
Request = REQ-00042
```

После Rename она сама об этом не узнает, если интеграция не предусматривает синхронизацию.

Поэтому чем больше внешних систем используют `name`, тем осторожнее нужно менять naming strategy.

Хороший ID обычно:

- уникален;
- стабилен;
- не зависит от часто меняющихся данных;
- не содержит лишнего смысла.

## 19. Как выбрать Naming Method

Можно пользоваться такой шпаргалкой:

```text
Есть естественный стабильный уникальный код?
→ By fieldname или Set by user

Нужен понятный номер вида REQ-00001?
→ Naming Series

Нужно составное имя из нескольких частей?
→ Expression

Человеку ID не важен, нужен машинный уникальный ключ?
→ UUID / Random

Логика совсем нестандартная?
→ By script
```

## Мини-практика

Выбери naming для четырёх случаев:

1. Справочник валют `EUR`, `USD`, `RUB` → **Set by user / By fieldname**.
2. Заявки `REQ-00001` → **Naming Series**.
3. Машинные записи интеграции, которые человек почти не видит → **UUID**.
4. Название заявки «Проверить отчёт» → лучше **Title Field**, а не обязательно `name`.

## Что запомнить

- `name` — системный уникальный идентификатор Document.
- `Title Field` нужен для удобного отображения и может отличаться от `name`.
- Frappe уже имеет несколько штатных Naming Methods.
- Rename — отдельная операция, а не обычное редактирование поля.
- Чем больше интеграций используют `name`, тем важнее его стабильность.
