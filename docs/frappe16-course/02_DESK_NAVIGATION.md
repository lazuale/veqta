# 02. Desk, Desktop, Sidebar, Workspace и навигация Frappe 16

Теперь разберём то, что пользователь видит глазами после входа в Frappe.

В этой главе не нужно ничего программировать. Задача проще: открыть Desk и понимать, **что перед тобой за экран и как он связан с данными**.

Проверено: **2026-08-30**.

## 1. Desk — рабочий интерфейс Frappe

`Desk` — встроенный интерфейс для системных пользователей. Обычно он доступен по пути:

```text
/app
```

Через него пользователь открывает списки, формы, отчёты, Workspaces, настройки, пользователей и другие объекты.

Если совсем просто:

> **Desk — это оболочка, внутри которой Frappe показывает рабочие экраны.**

Сам Frappe шире Desk: у Framework есть REST API, Web Forms, фоновые задачи, email, печать и другие механизмы, которые могут работать вообще без этого интерфейса.

## 2. Как выглядит Desk в v16

Упрощённо экран можно представить так:

```text
┌───────────────┬──────────────────────────────┐
│ Sidebar       │ Текущий экран               │
│               │                              │
│ поиск         │ Workspace / List / Form     │
│ навигация     │ Report / Settings / ...     │
│ уведомления   │                              │
│ профиль       │                              │
└───────────────┴──────────────────────────────┘
```

В v16 боковая навигация стала постоянной частью интерфейса. Поэтому старые видео по Frappe могут выглядеть заметно иначе.

## 3. Sidebar

`Sidebar` — левая навигационная область Desk.

Она помогает переходить между рабочими разделами, искать объекты, видеть уведомления и добираться до пользовательского меню.

Её полезно воспринимать как **главное меню Desk**, а не как отдельную бизнес-сущность.

Если тебе нужен новый раздел в меню, это ещё не означает, что нужен новый DocType.

## 4. Awesomebar — самый быстрый способ что-то найти

Глобальный поиск Frappe обычно называют `Awesomebar`.

Через него можно быстро найти, например:

```text
User
DocType
Role Permission Manager
Report
конкретный Document
```

Для новичка это очень полезная привычка: **не пытаться помнить, в каком меню спрятана настройка, а сначала искать её по названию**.

### Мини-пример

Нужно открыть список пользователей.

Вместо блуждания по меню:

```text
поиск → User → открыть список
```

Позже, когда интерфейс запомнится, меню начнёт работать само собой.

## 5. Desktop и Workspace

Эти слова похожи, но означают не одно и то же.

### Desktop

`Desktop` в v16 служит верхним уровнем входа в доступные рабочие области.

Условно:

```text
Desktop
├── Requests
├── Administration
├── Reports
└── My Workspace
```

### Workspace

`Workspace` — конкретная рабочая страница внутри Desk.

Она может содержать:

- ссылки и быстрые действия;
- маленькие списки документов;
- Number Cards;
- Charts;
- Onboarding;
- текстовые блоки и заголовки.

Пример простого Workspace:

```text
REQUESTS

Открытые: 24       Просроченные: 3

[Новая заявка]     [Все заявки]

Последние заявки
REQ-001
REQ-002
REQ-003
```

Такой экран можно собрать штатно, без отдельного frontend-приложения.

## 6. Public и Private Workspace

`Public Workspace` предназначен для общей навигации пользователей, которым он доступен.

`Private Workspace` — персональная страница конкретного пользователя.

На пальцах:

```text
Public  → «наш общий рабочий раздел»
Private → «мой личный рабочий стол»
```

Персональный Workspace удобен для своих ссылок и отчётов, но критическая логика приложения не должна зависеть от личной страницы одного человека.

## 7. Один DocType — несколько экранов

Это одна из ключевых идей Desk.

Допустим, есть один DocType:

```text
Request
```

С теми же самыми Documents можно работать по-разному:

```text
List View     → таблица заявок
Form View     → одна заявка
Kanban        → заявки по колонкам статуса
Calendar      → заявки по датам
Report        → выборка и аналитика
```

То есть новый способ просмотра данных **не обязательно означает новый тип данных**.

## 8. List View

`List View` — экран со множеством документов одного DocType.

Например:

```text
REQ-001   Купить бумагу       Open
REQ-002   Проверить отчёт     In Progress
REQ-003   Обновить шаблон     Done
```

Здесь обычно выполняют повседневную работу:

- ищут документы;
- фильтруют;
- сортируют;
- открывают записи;
- выполняют массовые действия;
- переключаются на другие представления.

### Фильтры

Например:

```text
Status = Open
Priority = High
```

Это всё ещё тот же DocType `Request`. Мы просто показываем часть его документов.

## 9. Form View

`Form View` — экран одного Document.

Открыли:

```text
REQ-002
```

и увидели его поля, кнопки, Timeline, attachments и доступные действия.

Большая часть формы строится из metadata DocType и DocField. Поэтому базовую форму обычно не приходится писать вручную.

Form View подробно разберём в отдельной главе.

## 10. Kanban — хороший пример разницы между данными и представлением

Пусть у `Request` есть поле `status`.

Те же документы можно показать так:

```text
NEW            IN PROGRESS       DONE
REQ-001        REQ-002           REQ-004
REQ-003        REQ-005
```

Здесь:

- `Request` — тип данных;
- `status` — поле документа;
- Kanban — способ показать документы.

Это простое различие потом сильно помогает не плодить лишние сущности.

## 11. Shortcut, Quick List, Number Card и Chart

На Workspace часто встречаются четыре полезных элемента.

| Элемент | Что делает | Пример |
|---|---|---|
| **Shortcut** | быстрый переход | «Открытые заявки» |
| **Quick List** | маленький список документов | последние 5 заявок |
| **Number Card** | одно число | `Просрочено: 7` |
| **Chart** | простой график | заявки по статусам |

Не нужно сейчас изучать их настройки. Важно понимать, что это **готовые элементы интерфейса**, а не отдельные приложения.

## 12. System User и Website User

Desk предназначен прежде всего для `System User`.

Если внешнему человеку нужно только заполнить форму, ему не обязательно давать полный Desk.

Упрощённо:

```text
сотрудник системы → Desk
внешний пользователь → Web Form / website-интерфейс
```

Web Forms и website-возможности будут отдельным блоком курса.

## 13. Когда нужен собственный frontend

На старте легко посмотреть на Desk и решить: «Я лучше сразу сделаю своё меню и свои страницы».

Не спеши.

Сначала стоит проверить, закрывают ли задачу:

- Form View;
- List View;
- Workspace;
- Kanban/Calendar/Gantt/Tree;
- Reports;
- штатные настройки отображения.

Свой frontend имеет смысл, когда найдено **конкретное ограничение**, а не просто потому, что стандартный Desk непривычен.

## Мини-практика

На чистом Site попробуй сделать четыре действия:

1. Открой `/app`.
2. Через поиск найди `User`.
3. Открой любой список документов и затем одну запись.
4. Вернись на Workspace и найди хотя бы один Shortcut или другой блок.

После этого попробуй вслух назвать, что ты сейчас видишь: `Sidebar`, `Workspace`, `List View` или `Form View`.

## Что запомнить

- **Desk** — встроенная рабочая оболочка Frappe.
- **Workspace** — рабочая страница, а не тип бизнес-данных.
- **List и Form** — два базовых представления одного DocType.
- Один набор Documents можно показывать разными Views.
- В v16 навигация отличается от старых версий, поэтому старые видео не всегда совпадают с экраном.
