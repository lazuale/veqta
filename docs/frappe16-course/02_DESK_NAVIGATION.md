# 02. Desk, Desktop, Sidebar, Workspace и навигация Frappe 16

В лабораторной 01 ты увидел структуру стенда на диске и открыл системный `User` в браузере.

Теперь нужно научиться ориентироваться в самом Desk: понимать, где ты находишься, как открыть нужный объект и чем отличаются Workspace, List View и Form View.

Новых бизнес-объектов в этой главе по-прежнему не создаём. Используем только то, что уже есть в чистом Framework.

Проверено для **Frappe Framework v16.32.0**.

---

## Что уже есть на стенде

Состояние не изменилось после лабораторной 01:

```text
Bench:          ~/frappe/frappe16-course-bench
Site:           learn.localhost
Apps installed: frappe, training
Module:         Training
Developer Mode: включён
User:           Administrator
Request:        ещё не создан
```

Desk открывается по:

```text
http://learn.localhost:8000
```

После входа внутренние рабочие маршруты Frappe используют `/app`.

---

## Какую проблему решаем сейчас

Frappe уже содержит много системных DocTypes и настроек. Если пытаться запоминать, в каком меню находится каждый экран, новичок быстро теряется.

Нужна более простая модель:

```text
Desk
├── Sidebar / Desktop      → куда перейти
├── Workspace              → рабочая страница
├── List View              → много Documents одного DocType
└── Form View              → один Document
```

И основной инструмент перехода:

```text
поиск Desk / Awesome Bar
```

---

## Desk

`Desk` — встроенный внутренний интерфейс Frappe для системных пользователей.

Через него открываются:

```text
Workspaces
Lists
Forms
Reports
настройки
системные DocTypes
```

Desk — только один из способов работать с Frappe. Позже в курсе появятся Web Form, REST API и другие интерфейсы, но сейчас они не нужны.

На этом этапе достаточно:

> Desk — это рабочая оболочка, внутри которой мы открываем разные представления данных и настроек.

---

## Что изменилось в навигации v16

В Frappe 16 появился постоянный Sidebar и отдельный Desktop для навигации по публичным Workspaces.

Поэтому старые видео и статьи по v14/v15 могут показывать другой стартовый экран или другое расположение навигации.

Для этого курса источником истины является живой `v16.32.0` на `learn.localhost`.

---

## Sidebar

`Sidebar` — постоянная боковая область навигации Desk.

Через неё можно переходить между доступными рабочими областями и возвращаться к основным разделам интерфейса.

Sidebar не является DocType твоей будущей предметной модели. Это часть интерфейса Desk.

Если в Sidebar виден какой-то раздел, это не означает, что перед тобой новый тип данных.

---

## Desktop

`Desktop` в v16 показывает доступные публичные Workspaces как верхний уровень навигации.

Упрощённо:

```text
Desktop
├── Workspace A
├── Workspace B
└── Workspace C
```

Сейчас нам не нужно создавать свой Workspace. В блоке интерфейса это будет отдельная практическая тема.

В этой главе достаточно научиться узнавать Desktop и переходить с него в существующие Workspaces.

---

## Workspace

`Workspace` — рабочая страница внутри Desk.

Она может собирать ссылки, быстрые действия, небольшие списки, карточки и другие готовые блоки Frappe.

Главное различие:

```text
Workspace
→ помогает собрать навигацию и рабочую информацию

DocType
→ описывает тип данных
```

Workspace не заменяет DocType и не создаёт новый тип Documents сам по себе.

В этой главе мы только открываем существующий Workspace. Создавать и настраивать собственный будем позже.

---

## Поиск Desk / Awesome Bar

Самый надёжный способ новичку найти системный объект — использовать глобальный поиск Desk.

Например, вместо попытки вспомнить меню можно ввести:

```text
User
DocType
Role
Workspace
System Settings
```

Поиск помогает перейти к существующему объекту. Он ничего не создаёт автоматически.

Это важная привычка для всего курса:

```text
не знаю, где находится системный объект
→ сначала ищу его по имени
```

---

## List View

`List View` показывает несколько Documents одного DocType.

На текущем стенде используем уже знакомый системный DocType:

```text
User
```

Когда ты открываешь список пользователей, перед тобой не «модуль пользователей» и не отдельное приложение.

Перед тобой:

```text
DocType: User
View:    List
```

В списке находятся Documents этого DocType, например:

```text
Administrator
Guest
```

Конкретный набор системных пользователей может отличаться, поэтому в лабораторной обязательным примером будет `Administrator`, который уже существует на нашем Site.

---

## Form View

`Form View` показывает один Document.

Если из списка `User` открыть `Administrator`, получится:

```text
DocType:  User
Document: Administrator
View:     Form
```

Это тот же Document, который мы использовали в лабораторной 01, но теперь внимание направлено не на термин `Document`, а на тип экрана.

Получается:

```text
User List
→ List View

Administrator
→ Form View
```

---

## Route в браузере

Когда ты переходишь между экранами Desk, меняется адрес после `/app`.

Например, для DocType `User` List View обычно имеет route вида:

```text
/app/user
```

А форма конкретного пользователя включает имя Document в route.

Не нужно сейчас учить правила построения всех URL.

Нужно только заметить причинно-следственную связь:

```text
открыл другой экран в Desk
→ изменился route
```

Позже это поможет понимать Web Form, REST и собственные Desk Page, но сейчас мы на этом не забегаем вперёд.

---

## Один объект можно видеть в разных представлениях

На примере `User` уже видно:

```text
DocType User
├── List View
└── Form View конкретного User
```

Когда в главе 4 появится `Request`, тот же принцип будет работать для нашего учебного объекта.

Дальше курс добавит другие представления постепенно, когда для них появятся нужные поля и данные.

Не нужно создавать отдельный DocType только потому, что нужен другой экран для тех же Documents.

---

## Public и Private Workspace

У Workspace есть два важных сценария:

```text
Public Workspace
→ общая рабочая область, доступная пользователям согласно настройкам

Private Workspace
→ личная рабочая область конкретного пользователя
```

Сейчас это только граница понятия.

Мы не создаём ни Public, ни Private Workspace в блоке A, потому что сначала нужен собственный `Request`, который появится в следующем блоке.

---

## Что не нужно путать

### Workspace и DocType

```text
Workspace → страница интерфейса
DocType   → модель типа Documents
```

### List View и новый тип данных

```text
List View → способ показать Documents
```

Сам по себе новый список не означает новый DocType.

### Sidebar и Module

```text
Sidebar → навигация Desk
Module  → логическая область App
```

Они могут быть связаны через интерфейс, но это разные понятия.

---

## Что произойдёт в лабораторной

Ты войдёшь как `Administrator` и последовательно откроешь:

```text
Desktop / Workspace
User List
Administrator Form
DocType List
Role List
System Settings
```

На каждом шаге будешь определять тип текущего экрана:

```text
Workspace
List View
Form View
```

Затем изменишь способ навигации: сначала найдёшь объект через поиск, потом вернёшься через Sidebar/Desktop.

В конце намеренно откроешь несуществующий route и убедишься, что Desk не создаёт экран только потому, что адрес был введён вручную.

После восстановления стенд останется без изменений.

---

## Что запомнить

1. `Desk` — внутренний рабочий интерфейс Frappe.
2. В v16 постоянный Sidebar является частью новой навигации.
3. `Desktop` помогает входить в публичные Workspaces.
4. `Workspace` — рабочая страница, а не тип данных.
5. `List View` показывает много Documents одного DocType.
6. `Form View` показывает один Document.
7. Поиск Desk — основной способ быстро найти существующий системный объект.
8. Route меняется вместе с открытым экраном, но правила URL подробно изучать пока не нужно.
