# Начало практикума

Это основной маршрут ученика. Остальные документы не нужно читать подряд до начала
работы.

## Для кого курс

Курс рассчитан на человека, который уверенно пользуется Windows и браузером, но может
не знать Linux, Git, Python, JavaScript, SQL, HTTP и устройство Frappe.

В основном маршруте не требуется писать Python или JavaScript. Небольшие изменения в
`hooks.py` — это конфигурация поставки app: список fixtures и запись для Apps Page.

## Что понадобится

- Windows 11 с доступным WSL2;
- не менее 8 GB оперативной памяти на компьютере;
- стабильное подключение к интернету во время установки;
- редактор обычного текста, например Visual Studio Code;
- отдельное время: не выполнять первые лабораторные на рабочем сервере.

Все команды выполняются в Debian внутри WSL2, если рядом не написано `PowerShell`.
Команды SQL выполняются только после входа в консоль MariaDB.

## Как выполнять лабораторную

Внутри каждого проекта должны быть закрыты пять видов работы. Они не обязаны повторяться
отдельными одинаковыми заголовками в каждом номерном шаге:

1. **Исходное состояние** — понятно, что уже должно существовать до действия.
2. **Действия** — команды и настройки, которые меняют продукт или site.
3. **Проверка** — видимый результат и, где требуется гарантия, отрицательный сценарий.
4. **Source check** — понятно, что попало в репозиторий app, а что осталось в базе site.
5. **Состояние после** — можно однозначно решить, готов ли стенд к следующему шагу.

Не переходить дальше, если итоговое состояние не совпало. Сначала открыть
[TROUBLESHOOTING.md](TROUBLESHOOTING.md), затем сравнить последнее изменение через
`git diff`.

## Как читать команды

Знак приглашения терминала не копируется. В записи:

```text
dev@first:~/frappe/frappe-practicum-bench$
```

команда начинается после `$`.

Многострочный блок копируется целиком. Перед командой с `cd` проверить текущий каталог:

```bash
pwd
```

Если лабораторная говорит «из bench», ожидается:

```text
~/frappe/frappe-practicum-bench
```

Если она говорит «из репозитория app», ожидается один из каталогов:

```text
~/frappe/frappe-practicum-bench/apps/equipment_register
~/frappe/frappe-practicum-bench/apps/purchase_requests
~/frappe/frappe-practicum-bench/apps/service_intake
```

## Что записывать

Для каждой лабораторной вести короткий протокол:

```text
Лабораторная:
Дата:
Рабочий site:
Проверка прошла:
Отрицательная проверка прошла:
Commit:
Замечания:
```

Для существенной гарантии в замечании достаточно указать фактический результат и слой,
который его обеспечил. Полный формат и примеры приведены в
[ACCEPTANCE.md](ACCEPTANCE.md).

Пароли, API keys, API secrets и SMTP credentials в протокол не записываются.

## Когда можно исправлять отклонения

Можно:

- повторить последнюю настройку;
- удалить собственный тестовый документ;
- исправить поле до следующей лабораторной;
- пересоздать чистый приёмочный site;
- откатить учебный эксперимент с Share или User Permission.

Нельзя молча:

- переустанавливать рабочий app;
- копировать базу рабочего site на чистый site;
- создавать недостающий Workflow вручную после `install-app`;
- выполнять задания как Administrator вместо проверки целевой роли;
- добавлять Python/JavaScript, чтобы обойти непонятную настройку.

## Критерий окончания

Практикум закончен, когда три app устанавливаются на новые site, рабочие данные не
попадают в исходники, permissions проверены отдельными пользователями, а ученик может
объяснить, почему каждый применённый механизм нужен продукту.
