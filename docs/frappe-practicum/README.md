# Практикумы Frappe Framework 16

Практикумы нужны для одного: изучить Frappe нативно, собирая на нём реальные рабочие системы.

Это не курс «no-code» и не курс программирования. Мы используем Frappe так, как он задуман: создаём app, устанавливаем его на site, работаем в Developer Mode, создаём Module и DocType, настраиваем права, Workflow, отчёты, Workspace, автоматизацию и Web Form. Код появляется только там, где он действительно нужен самому Frappe-механизму, например в простом условном выражении. Собственную бизнес-логику на Python или JavaScript в базовых практикумах не пишем.

## Проверенная версия

Целевая линия курса: **Frappe Framework v16**.

Базовая версия для проверки программы: **v16.32.0**.

При подготовке каждого пошагового практикума поведение сверяется с:

- официальной документацией Frappe;
- веткой `version-16` репозитория `frappe/frappe`;
- фактическим учебным стендом.

Если следующий релиз v16 меняет интерфейс или поведение функции, сначала обновляется документация курса, затем сам практикум.

## Как учимся

Каждый проект начинается с задачи, а не с перечня функций.

Например:

- нужно хранить связанные сущности — создаём DocType и Link;
- нужны повторяющиеся строки документа — используем Child Table;
- нужно изменить существующий DocType без правки исходников — используем Customize Form;
- нужно разделить доступ — настраиваем Roles и Permissions;
- нужно назначить ответственному работу — используем Assign To и ToDo;
- нужен управляемый маршрут — строим Workflow;
- нужно регулярно создавать документы — используем Auto Repeat;
- нужно распределять входящую работу — используем Assignment Rule;
- нужны сводки — строим Report Builder, Number Card и Dashboard Chart;
- нужен рабочий экран — собираем Workspace;
- нужен внешний ввод — создаём Web Form.

Функция не добавляется в проект ради галочки. Она появляется там, где решает понятную задачу.

## Программа

### P0. Учебное приложение

Создаём настоящий Frappe app и учебный site.

Практика:

- установка Frappe v16;
- создание site;
- `bench new-app`;
- установка app на site;
- включение Developer Mode;
- создание Module;
- знакомство со структурой app;
- понимание, где Frappe хранит метаданные DocType;
- проверка Desk, scheduler/background workers и PDF;
- фиксация учебного app в Git.

Результат: рабочая среда, в которой все дальнейшие объекты принадлежат учебному приложению и нормально версионируются.

### P1. Реестр оборудования

Строим первую предметную модель внутри своего app.

Практика:

- обычный DocType;
- Child DocType;
- Single DocType;
- основные Field Types;
- Link и Dynamic Link;
- Naming и Title Field;
- Form Builder;
- Section, Column и Tab Break;
- Quick Entry;
- Search Fields;
- Track Changes;
- List View;
- фильтры и сортировка;
- импорт и экспорт;
- вложения и изображения.

Результат: полноценный объектный реестр, собранный как нормальная часть Frappe app.

### P2. Настройка существующих форм и рабочего интерфейса

Учимся отличать разработку собственных DocType от site-specific настройки уже существующих.

Практика:

- Customize Form;
- Custom Field;
- Property Setter;
- изменение подписей, порядка и свойств полей;
- List View и сохранённые фильтры;
- Quick Entry и preview;
- Workspace;
- Shortcuts;
- Quick Lists;
- связи и действия DocType там, где они уместны.

Результат: ученик понимает две нормальные модели Frappe — стандартный объект приложения и кастомизация существующего объекта на конкретном site.

### P3. Внутренние заявки

Строим многопользовательскую систему работы.

Практика:

- User;
- Role;
- Role Permission Manager;
- Create / Read / Write / Delete;
- If Owner;
- Permission Level;
- User Permission;
- Share;
- Assign To;
- ToDo;
- Due Date;
- Priority;
- Comments;
- Timeline;
- Tags;
- Kanban.

Результат: система заявок, где отдельно работают доступ к данным и ответственность за работу.

### P4. Согласование закупки

Строим управляемый жизненный цикл документа.

Практика:

- Is Submittable;
- Draft / Submit / Cancel / Amend;
- DocStatus;
- прикладной Status;
- Workflow State;
- Workflow Action Master;
- Workflow Transition;
- роли переходов;
- Workflow Action как фактическая запись ожидающего действия;
- простые штатные условия переходов, если они нужны.

Результат: понятное согласование без подмены Workflow обычным полем статуса.

### P5. Журнал проверок

Учимся работать с накопленными данными, а не только вводить их.

Практика:

- Calendar;
- Report Builder;
- фильтры;
- Group By;
- Count / Sum / Average;
- Number Card;
- Dashboard Chart;
- Workspace;
- Print View;
- Print Format Builder;
- Letter Head;
- PDF.

Результат: система проверок с календарём, отчётами, показателями, печатной формой и рабочим экраном.

### P6. Регламентные работы и автоматизация

Разбираем штатные механизмы автоматизации отдельно, не сваливая их в одну цепочку.

Практика:

- Allow Auto Repeat;
- Auto Repeat;
- периодичность;
- Assignee;
- создание отдельных документов для исполнителей;
- Assignment Rule;
- Round Robin;
- Load Balancing;
- Based on Field;
- Weighted Distribution;
- простое встроенное PythonExpression в Assignment Rule;
- Notification;
- System Notification;
- Filters-условия Notification;
- scheduler и фоновые задачи на уровне пользователя.

Результат: ученик понимает, какой штатный механизм использовать для повторения, распределения и уведомлений.

### P7. Приём обращений через Web Form

Выводим часть приложения за пределы Desk.

Практика:

- Web Form;
- Route;
- Anonymous responses;
- Login Required;
- Apply document permissions;
- Allow editing after submit;
- Allow multiple responses;
- Show list;
- Attachments;
- Comments;
- Print;
- Web Form Request / Key required как дополнительный сценарий.

Результат: внешний пользователь создаёт или редактирует обычный Frappe Document, который затем обрабатывается в Desk.

### P8. Итоговый проект «Операционный центр»

Ученик получает техническое задание и сам проектирует приложение.

В итоговой работе должны естественно применяться основные блоки курса:

- app и Module;
- связанные DocType;
- Child Table;
- подходящие Field Types;
- Naming;
- роли и права;
- назначения;
- Workflow;
- отчёты;
- Workspace;
- печать;
- автоматизация;
- Web Form.

P8 не повторяет предыдущие инструкции. Он проверяет, умеет ли человек выбрать правильный штатный механизм Frappe для новой задачи.

## Что должен понимать выпускник

После курса человек должен уметь:

1. объяснить разницу между Bench, site, app, Module и DocType;
2. создать и установить своё Frappe app;
3. собрать модель данных внутри app;
4. понимать разницу между стандартным DocType приложения и Customize Form;
5. выбирать подходящие Field Types и связи;
6. настраивать формы, списки, поиск и Naming;
7. проектировать роли и ограничения доступа;
8. отдельно использовать Permissions и Assignment;
9. работать с Draft / Submit / Cancel / Amend;
10. строить простой Workflow;
11. создавать no-code отчёты и рабочие панели;
12. делать печатные формы;
13. настраивать штатную автоматизацию;
14. публиковать Web Form;
15. понимать, где заканчиваются штатные возможности и начинается необходимость в собственной программной логике.
