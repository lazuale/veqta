# Практикумы Frappe Framework 16

Статус: **утверждённая базовая архитектура практикумов**  
Уровень: **базовый / без программирования**  
Платформа: **Frappe Framework 16**

## Назначение

Этот раздел репозитория описывает практический курс по штатным возможностям Frappe Framework 16.

Курс предназначен для человека без навыков программирования. Обучение строится не как справочник функций и не как последовательность экранов Frappe, а как серия законченных проектов. Каждый проект решает понятную прикладную задачу, вводит ограниченный набор новых механизмов Frappe и повторно использует уже изученные.

Цель базового уровня — научиться самостоятельно собирать небольшие рабочие информационные системы штатными средствами Frappe и понимать границу, после которой уже требуется scripting или полноценная разработка.

## Основной принцип

> Сначала возникает практическая задача, затем выбирается штатный механизм Frappe, который её решает.

Практикум не должен сводиться к формату «найдите ещё одну кнопку». Каждый механизм вводится только в естественном для него сценарии.

Примеры:

- несколько связанных сущностей → `DocType` + `Link`;
- повторяющиеся строки документа → `Child Table`;
- разные права пользователей → `Role` + `Permissions`;
- назначение ответственного → `Assign To` + `ToDo`;
- управляемое согласование → `Workflow`;
- повторяющаяся работа → `Auto Repeat`;
- автоматическое распределение → `Assignment Rule`;
- сводка для пользователя → `Report Builder` + `Number Card` + `Chart` + `Workspace`;
- ввод данных вне Desk → `Web Form`.

## Линейка проектов

### P0. Учебный стенд

Подготовить чистый Frappe Framework 16, создать учебный site, войти в Desk, познакомиться с навигацией, пользователями и базовыми системными настройками.

**Результат:** воспроизводимый стенд, на котором выполняются все последующие проекты.

### P1. Реестр оборудования

Собрать объектный реестр с типами оборудования, местами размещения, карточками объектов и документами передачи.

**Основная тема:** модель данных.

**Новые механизмы:** DocType, поля, Naming, Link, Child Table, вложения, List View, фильтры, импорт и экспорт.

### P2. Внутренние заявки

Собрать многопользовательскую систему обработки внутренних обращений с заявителем, координатором и исполнителем.

**Основная тема:** люди, ответственность и доступ.

**Новые механизмы:** User, Role, Role Permissions, User Permission, Share, Assign To, ToDo, Comments, Timeline, Kanban.

### P3. Согласование закупки

Собрать управляемый маршрут согласования заявки с черновиком, утверждением, отклонением, Submit, Cancel и Amend.

**Основная тема:** жизненный цикл документа и бизнес-процесс.

**Новые механизмы:** Is Submittable, DocStatus, Permission Level, Workflow, Workflow State, Workflow Action, Transition.

### P4. Журнал проверок

Собрать систему контрольных мероприятий с чек-листами, результатами, фотографиями, календарём, отчётами, печатью и рабочей панелью.

**Основная тема:** контроль, представления и аналитика.

**Новые механизмы:** Calendar, Report Builder, агрегаты, Print Format Builder, PDF, Number Card, Dashboard Chart, Workspace.

### P5. Регламентные работы

Собрать контур повторяющихся работ, в котором Frappe создаёт очередной документ, назначает его пользователю и уведомляет о необходимости выполнения.

**Основная тема:** штатная автоматизация без кода.

**Новые механизмы:** Notification, Auto Repeat, Assignment Rule.

### P6. Приём обращений через Web Form

Собрать внешний интерфейс создания документов без разработки собственного frontend.

**Основная тема:** Website ↔ Desk.

**Новые механизмы:** Web Form, route, guest/login access, attachments, редактирование и список разрешённых документов.

### P7. Итоговый проект «Операционный центр»

На чистом стенде самостоятельно собрать небольшую систему управления операционной работой, объединив модель данных, доступ, назначения, workflow, автоматизацию, отчёты, workspace, печать и web-ввод.

**Основная тема:** самостоятельное проектирование.

P7 не является ещё одной пошаговой инструкцией. Это итоговая работа по техническому заданию.

## Что должен уметь выпускник базового уровня

После прохождения курса ученик должен уметь без программирования:

1. разложить прикладную задачу на сущности и документы;
2. определить необходимые DocType и связи между ними;
3. выбрать подходящие типы полей и структуру формы;
4. настроить Naming и читаемое отображение документов;
5. создать пользователей, роли и ограничения доступа;
6. организовать назначения и персональную очередь работы;
7. отличать обычный статус от Workflow State и DocStatus;
8. настроить простой Workflow;
9. настроить штатные уведомления, повторение и распределение;
10. построить no-code отчёт и рабочий Workspace;
11. подготовить печатное представление;
12. опубликовать Web Form;
13. проверить систему от имени нескольких пользователей;
14. определить, решается ли новая задача штатной конфигурацией или уже требует разработки.

## Критерий качества курса

Каждый проект обязан иметь:

- понятную прикладную задачу;
- конечный рабочий результат;
- явный перечень новых механизмов;
- повторение ранее изученного;
- тестовые данные;
- проверку от имени реальных ролей;
- контрольный сценарий;
- критерии приёмки;
- отсутствие скрытой зависимости от собственного кода.

Если функцию невозможно естественно применить в одном из проектов, она не должна искусственно добавляться ради галочки. Такие возможности относятся либо к дополнительному заданию, либо к следующему уровню курса.
