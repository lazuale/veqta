# Границы базового практикума

Статус: **обязательные ограничения**  
Платформа: **Frappe Framework 16**

## 1. Цель границ

Этот документ определяет, что считается допустимой реализацией в базовых практикумах.

Базовый курс изучает Frappe как конфигурируемую платформу. Ученик собирает рабочие системы через штатный интерфейс и штатные механизмы платформы, но не пишет собственное приложение и не программирует поведение системы.

Если для выполнения задания требуется написать код, такое задание не относится к базовому уровню.

## 2. Базовая среда

Все практикумы выполняются на:

- Frappe Framework 16;
- чистом учебном site;
- стандартном Desk;
- стандартной Website/Web Form части Frappe;
- штатных фоновых задачах и scheduler там, где они необходимы встроенным функциям.

Практикум не должен предполагать наличие ERPNext или другого стороннего приложения, если это прямо не обозначено как отдельный дополнительный стенд. Основная программа обязана проходиться на Frappe Framework.

## 4. Допустимый low-code

В базовом курсе термин `low-code` означает только настройку встроенных механизмов Frappe через штатные формы и конструкторы.

Допустимы:

- настройка Workflow;
- настройка Notification;
- настройка Auto Repeat;
- настройка Assignment Rule;
- Report Builder;
- Workspace Builder;
- Print Format Builder;
- Web Form Builder;
- стандартные поля условий, если их можно заполнить как часть штатной настройки и для прохождения не требуется создавать отдельный скрипт или модуль.

Low-code в этом курсе не означает написание произвольного Python или JavaScript.

## 5. Что запрещено в базовом уровне

Не используются:

- собственное Frappe App;
- Python;
- JavaScript;
- Client Script;
- Server Script;
- hooks.py;
- controllers;
- собственные whitelisted methods;
- SQL;
- Query Report;
- Script Report;
- произвольные API-вызовы;
- REST-интеграции;
- Webhook-интеграции;
- Jinja;
- ручной HTML-шаблон печати;
- Custom HTML для реализации обязательной логики;
- собственный CSS как условие прохождения;
- собственные Website/Portal Pages;
- Virtual DocType;
- внешние библиотеки;
- сторонние приложения и плагины как обязательная зависимость.

## 6. Что не считается нарушением

Не является сторонней разработкой:

- создание custom DocType через Desk;
- создание полей и связей через UI;
- настройка ролей и прав;
- создание Workflow;
- создание отчёта через Report Builder;
- создание Workspace;
- настройка печати через визуальный builder;
- настройка Notification, Auto Repeat и Assignment Rule;
- создание Web Form;
- использование штатных фоновых задач Frappe этими механизмами.

## 8. Правило отбора функций

Функция входит в обязательную базовую программу только если одновременно выполняются три условия:

1. она является штатной возможностью Frappe Framework 16;
2. её можно применить без собственного программного кода;
3. для неё существует естественная прикладная задача в одном из практикумов.

Если хотя бы одно условие не выполняется, функция не должна искусственно включаться в базовую матрицу ради формального «100% покрытия».

## 9. Правило разрешения спорных случаев

Если при подготовке конкретного урока возникает сомнение, относится ли механизм к базовому уровню:

1. проверяется его наличие в Frappe Framework 16;
2. проверяется, может ли ученик настроить его из UI без собственного кода;
3. проверяется, не зависит ли он от ERPNext или другого приложения;
4. проверяется, можно ли построить воспроизводимое задание на чистом учебном site;
5. только после этого механизм добавляется в урок и в `MATRIX.md`.

До такой проверки спорный механизм считается **необязательным**.
