# VEQTA — журнал решений

Этот файл содержит **текущее состояние решений**, а не полный пересказ обсуждений. Предыдущие формулировки остаются в Git history.

## Принято

### D-001 — Frappe Framework является технической платформой

VEQTA строится как самостоятельное приложение на Frappe Framework, без ERPNext как обязательной основы.

### D-002 — Не строим framework поверх Frappe

VEQTA не создаёт собственные ORM, RBAC, form builder, notification engine, plugin framework или workflow platform, пока конкретное требование не доказало недостаточность штатного Frappe.

### D-003 — Пользователь задаёт процесс

VEQTA не навязывает Scrum, Kanban, ITIL, Project Management или другую методологию. Типы работы, состояния, Workflow, роли, формы и представления по возможности настраиваются штатными средствами Frappe.

### D-004 — Гибкость не должна разрушать данные

Принципы данных:

- один бизнес-факт — один источник истины;
- ключевые факты структурированы;
- JSON/EAV не являются основой Core;
- производные метрики не хранятся как первичные факты без необходимости;
- аналитически важная история должна быть машинно читаемой.

### D-005 — OLTP является источником истины

VEQTA Core хранит операционные первичные данные. DWH/OLAP не является частью первого ядра и при необходимости строится отдельно.

### D-006 — Core начинается с минимальной модели

До результатов prototype v0.1 проверяются только:

- `Work Item`;
- `Work Type`;
- State через штатные возможности Frappe.

Новые Core-сущности не добавляются заранее.

### D-007 — GitHub является источником истины проекта

Согласованные решения и реальное воспроизводимое состояние продукта фиксируются в `lazuale/veqta`. Чат является рабочим обсуждением, но не спецификацией.

### D-008 — Решения сверяются только с актуальным stable Frappe

Перед утверждением возможностей/ограничений Frappe проверяются официальная документация и, когда это существенно, официальный исходный код текущей stable-линии.

На 2026-08-29 рабочая линия prototype: `version-16`, последняя проверенная stable-версия: `v16.32.0`.

Подробные правила: `DEVELOPMENT.md`.

### D-009 — Стенд не является источником истины продукта

Согласованное изменение, сделанное через Desk, должно быть представлено файлами приложения или штатно экспортированной конфигурацией и запушено в `lazuale/veqta`.

Критерий: чистый совместимый Frappe site должен восстанавливать согласованную VEQTA из repository без повторного ручного накликивания продуктовой конфигурации.

### D-010 — До prototype не фиксируем собственный Assignment/Lifecycle engine

В v0.1 сначала проверяются:

- Frappe Workflow / Workflow State;
- Transition Conditions по `work_type`;
- Frappe Assign To / связанные `ToDo`;
- Frappe Version/Timeline;
- стандартный List/Kanban.

Собственный механизм создаётся только после конкретно воспроизведённого ограничения.

## Отброшенные направления

Следующее **не является текущей архитектурой**:

- заранее спроектированный большой VEQTA Kernel;
- Lifecycle Scheme / Responsibility Engine / Policy Layer без доказанной необходимости;
- собственный Event Bus/Event Store;
- микросервисы и множество Frappe apps с первого дня;
- ERPNext как обязательная база VEQTA;
- собственный workflow engine как исходная точка.

## Открытые вопросы prototype v0.1

### Q-001 — Минимальный Work Item

Подтвердить или изменить кандидат из `MODEL_V0_1.md`.

### Q-002 — Work Type

Проверить модель `code + title`, naming, rename и поведение ссылок.

### Q-003 — State / Workflow

Проверить, достаточно ли одного штатного Workflow для `Work Item` с ветвлением по `work_type`.

### Q-004 — State history

Проверить, достаточно ли Version/Timeline для нужной аналитики. `Work State Change` добавляется только при подтверждённой недостаточности.

### Q-005 — Assignment / ответственность

Проверить штатный Assign To / ToDo и решить, нужен ли VEQTA отдельный accountable owner вообще.

### Q-006 — Kanban

Проверить совместимость Workflow State с Kanban и drag-and-drop без обхода lifecycle rules.

### Q-007 — Workstream / Context

Не входит в Core до отдельного доказательства необходимости.

### Q-008 — Outcome

Не входит в Core до отдельного доказательства необходимости.

### Q-009 — Лицензия VEQTA

Репозиторий публичный, но лицензия продукта пока не выбрана. Решение необходимо до первого публичного релиза/распространения.
