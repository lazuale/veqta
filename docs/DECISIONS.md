# VEQTA — текущие решения

Этот файл описывает только актуальное состояние архитектуры. История изменений хранится в Git.

## Продукт

- VEQTA — самостоятельное приложение на Frappe Framework.
- VEQTA не требует ERPNext.
- Пользователь настраивает процесс преимущественно штатными средствами Frappe.
- VEQTA не навязывает Scrum, Kanban, ITIL или другую методологию.

## Платформа

- Целевая линия разработки — актуальный stable Frappe v16.
- Возможности Framework проверяются по официальной документации и исходникам используемой версии.
- Собственный механизм добавляется только если штатный Frappe не обеспечивает обязательное свойство VEQTA.

## Данные

- один бизнес-факт — один источник истины;
- ключевые данные структурированы и типизированы;
- JSON/EAV не являются основой Core;
- производные метрики не хранятся как первичные факты без необходимости;
- аналитически важная история должна быть машинно читаемой;
- VEQTA OLTP хранит первичные операционные данные; отдельный аналитический слой строится при необходимости.

## Core v0.1

На первом prototype проверяются:

- `Work Item`;
- `Work Type`;
- State через Frappe Workflow / Workflow State;
- штатный Assignment / `ToDo`;
- штатная история Frappe;
- List / Kanban.

Текущая модель описана в `MODEL_V0_1.md`.

## Репозиторий

`lazuale/veqta` — источник истины продукта. Согласованная конфигурация dev-site должна быть представлена файлами приложения или штатно экспортированной конфигурацией и воспроизводиться на чистом совместимом site.

## Лицензия

VEQTA: **AGPL-3.0-or-later**. Frappe Framework остаётся отдельной MIT-зависимостью.

## Открытые архитектурные вопросы v0.1

После живого prototype нужно решить только три развилки:

1. достаточно ли штатного Frappe Workflow для lifecycle `Work Item`;
2. достаточно ли Assignment / `ToDo` для модели назначения VEQTA;
3. достаточно ли штатной истории Frappe или нужен структурированный `Work State Change`.

Остальные проверки первого стенда — реализационные и compatibility-тесты; они ведутся в Issue #1 и `PROTOTYPE_V0_1.md`.
