## Правила написания

1. Одна работа — один осмысленный прирост проекта.
2. Не превращать работу в справочник по всем настройкам экрана.
3. Не использовать возможность до того, как её prerequisite пройден в предыдущих работах.
4. Все действия выполняются на одном сквозном учебном Site.
5. Использовать реальные тестовые записи, а не абстрактные примеры.
6. После каждого важного шага указывать ожидаемый результат.
7. Обязательно проверять permissions под обычными пользователями, а не только Administrator.
8. Если механизм можно проверить ошибочной конфигурацией, ученик должен увидеть и неправильный результат.
9. Не использовать Python, JavaScript, SQL, Server Script или собственный app-код.
10. Не добавлять advanced-функциональность в основной маршрут только ради полноты.
