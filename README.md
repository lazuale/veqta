# VEQTA

VEQTA — проект приложения на **Frappe Framework** для управления рабочими единицами через настраиваемый процесс.

> **Frappe даёт инструменты. VEQTA даёт модель работы. Пользователь задаёт процесс.**

## Зачем этот проект

Готовые системы часто заставляют описывать работу их терминами: проектами, тикетами, спринтами, заявками и заранее заданными процессами.

В VEQTA сейчас проверяется более простой подход: оставить технические механизмы Frappe и добавить минимальную предметную модель, достаточную для обычной управляемой работы.

На первом prototype это выглядит так:

```text
Work Type  →  какой это вид работы
Work Item  →  конкретная единица работы
Workflow   →  в каком состоянии она находится и куда может перейти
Assign To  →  кому она назначена
History    →  как она проходила через состояния
```

Например, на одном и том же `Work Item` проверяются два вида работы:

```text
TASK:  New → In Progress → Done
CHECK: New → In Progress → Review → Done
```

Это не описание готового продукта. Это текущая гипотеза, которую должен подтвердить или опровергнуть живой стенд.

## Что именно проверяем в v0.1

### 1. Одна модель для разных видов работы

`Work Type` должен позволить отличать разные виды работы, не создавая отдельную сущность под каждый сценарий.

`Work Item` — сама единица управляемой работы.

### 2. Штатный Workflow Frappe

Проверяем, может ли один Frappe Workflow обслуживать `TASK` и `CHECK` с разными маршрутами и при этом реально запрещать недопустимые переходы.

### 3. Назначение исполнителей

Проверяем штатный `Assign To` и связанные `ToDo`: одного исполнителя, нескольких исполнителей и снятие одного назначения без повреждения остальных.

### 4. История состояний

Проверяем, можно ли из штатных `Version`, Timeline и Workflow comments получить нормальную машинно читаемую историю переходов: откуда, куда, кто и когда.

### 5. Desk и Kanban

Проверяем, можно ли реально работать с этой моделью через штатный интерфейс Frappe и не обходит ли Kanban правила Workflow при drag-and-drop.

### 6. Стенд → Git

То, что принято на dev-стенде, должно существовать как воспроизводимый код или штатно экспортированная конфигурация приложения.

Контрольный результат:

```text
чистый совместимый Frappe site
+ repository VEQTA
+ install-app / migrate
= то же принятое состояние без повторного ручного накликивания
```
