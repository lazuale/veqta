# VEQTA

**VEQTA** — open-source приложение на Frappe Framework для построения собственных процессов управления работой на общей структурированной модели данных.

> **Frappe даёт инструменты. VEQTA даёт модель работы. Пользователь задаёт процесс.**

## Зачем проект существует

Готовые системы управления работой часто заставляют команду подстраиваться под заранее заданные сущности, терминологию и методологию. VEQTA исследует другой подход: дать готовую, небольшую и аналитически пригодную основу управления работой, но оставить конкретный процесс пользователю.

VEQTA не должна становиться ни новым framework поверх Frappe, ни ERP/CRM/BPM-комбайном, ни универсальным no-code конструктором.

## Базовые принципы

- **Frappe — техническая платформа.** Не переписываем штатные возможности Framework без доказанной необходимости.
- **VEQTA — модель управляемой работы.** Код проекта появляется только там, где начинается собственная предметная логика VEQTA.
- **Процесс задаёт пользователь.** Типы работы, состояния, workflow, роли, представления и локальные поля настраиваются преимущественно штатными средствами Frappe.
- **Гибкость не должна разрушать данные.** Один факт — один источник истины; ключевые бизнес-факты структурированы и типизированы.
- **OLTP — источник истины.** Аналитические показатели производны и не должны засорять операционную модель.
- **Сначала простота.** Новая сущность, подсистема или модуль появляются только после доказанной необходимости.

## Текущий статус

Проект находится на стадии **prototype v0.1**: минимальная модель проверяется на актуальном стабильном Frappe штатными средствами Framework до написания собственных подсистем.

Текущая рабочая гипотеза ядра начинается с трёх понятий:

- `Work Item` — единица управляемой работы;
- `Work Type` — пользовательская классификация работы;
- `State` — текущее состояние работы.

Состав ядра **ещё не заморожен**. Каждая следующая сущность должна доказать необходимость на реальных сценариях.

## Начать разработку

Для локального prototype на Windows используется WSL2. Главная пошаговая инструкция:

- [Старт разработки на Windows + WSL2](docs/START_HERE_WSL2.md)

Рабочая среда строится так, чтобы исходники VEQTA и официальный исходник используемой версии Frappe находились рядом:

```text
veqta-bench/
└── apps/
    ├── frappe/   # официальный frappe/frappe текущего стенда
    └── veqta/    # lazuale/veqta
```

Это позволяет перед каждым техническим решением сверять документацию, реальный исходный код Frappe и поведение локального стенда.

## Принцип ведения проекта

GitHub — источник истины по принятым решениям VEQTA. Обсуждения могут происходить где угодно, но согласованные решения, изменения курса и открытые вопросы должны фиксироваться в репозитории.

Для технических решений действует последовательность:

> **Официальная документация → исходники текущего Frappe → живой тест → решение VEQTA → commit.**
