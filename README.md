# VEQTA

**VEQTA — независимая открытая инженерная и продуктовая экосистема, построенная на Frappe Framework.**

VEQTA работает как инженерная продуктовая студия: мы исследуем, как естественно и надёжно проектировать приложения на Frappe, превращаем подтверждённые инженерные решения в обучение и эталонные реализации, а зрелые решения — в самостоятельные открытые продукты.

> **Понять Frappe. Проверить решение. Выпустить полезный продукт.**

VEQTA не заменяет и не форкает Frappe Framework и не является официальным проектом Frappe Technologies. Frappe остаётся технологическим фундаментом.

## Язык проекта

VEQTA ориентирована прежде всего на русскоязычную аудиторию. **Русский язык является основным языком документации, обучения, инженерных материалов, управления проектом и публичной коммуникации.**

Английский сохраняется там, где он нужен для точности или совпадения с реальным Frappe и кодом: `DocType`, `Document`, `Workflow`, `App`, `Site`, `Bench`, REST API, имена методов, hooks, команд, пакетов и других технических контрактов.

Полное правило зафиксировано в [`LANGUAGE_POLICY.md`](LANGUAGE_POLICY.md).

### VEQTA Engineering

Инженерная база VEQTA: архитектурные стандарты, доказательства, паттерны, ограничения и правила принятия решений на Frappe.

Текущий основной материал — [`docs/frappe-architecture-standard/`](docs/frappe-architecture-standard/README.md). В ходе реорганизации он будет перенесён в `engineering/frappe/` без изменения своей роли как архитектурного стандарта, основанного на доказательствах.

### VEQTA Learn

Структурированное обучение проектированию на Frappe: учебные маршруты, практические курсы и упражнения.

Мы не строим курс как каталог функций Framework. Учебная последовательность должна объяснять, **какая ответственность появилась, какой механизм Frappe уже ей владеет и почему выбранное решение соответствует архитектуре Framework**.

Текущий baseline нового практикума находится в [`docs/frappe-training/`](docs/frappe-training/).

### VEQTA Labs

Изолированные эксперименты для проверки спорных архитектурных, продуктовых и UX-гипотез.

Lab может завершиться неудачей, стать эталонной реализацией, дать материал для Learn или перейти в инкубацию продукта. Эксперимент не считается продуктом только потому, что в нём уже есть рабочий код.

Существующий prototype `Work Type` / `Work Item` теперь классифицируется как будущий **VEQTA Labs / Work Management / v0.1**. Его текущие материалы пока остаются в `docs/` до физической миграции структуры репозитория.

### VEQTA Products

Самостоятельные продукты для реальной эксплуатации, решающие конкретные пользовательские задачи.

Для обычного Frappe-продукта нормальная программная граница — самостоятельно устанавливаемый Frappe `App` со своей областью ответственности, релизным циклом, документацией и продуктовой идентичностью. Дополнительный frontend, сервис или `App` допустимы только при реальной продуктовой ответственности и явном архитектурном решении.

VEQTA сама не является обязательным runtime `App` и заранее не вводит `veqta_core` поверх Frappe.

## Инженерный принцип

Для каждого требования сначала определяется ответственность, затем проверяется штатный механизм Frappe:

```text
требование
    ↓
какая ответственность нужна?
    ↓
какой механизм Frappe уже ей владеет?
    ↓
совпадает ли его семантика?
    ├── да → используем штатный механизм
    └── нет → ищем официальную точку расширения
                    ↓
          собственный механизм только при необходимости
```

Собственный код не является проблемой. Проблема — без причины дублировать ответственность, которой уже владеет Framework.

## Foundation baseline

Направление VEQTA фиксируется шестью базовыми документами:

1. [`PROJECT_CHARTER.md`](PROJECT_CHARTER.md) — что такое VEQTA, её миссия, границы и правила, которые нельзя менять неявно.
2. [`BRAND_ARCHITECTURE.md`](BRAND_ARCHITECTURE.md) — архитектура бренда, аудитории, именование и визуальные принципы.
3. [`ENGINEERING_PRINCIPLES.md`](ENGINEERING_PRINCIPLES.md) — общая инженерная дисциплина для Engineering, Learn, Labs и Products.
4. [`PRODUCT_LIFECYCLE.md`](PRODUCT_LIFECYCLE.md) — путь `Проблема → Lab → Эталон → Инкубация → Product`.
5. [`REPOSITORY_STRUCTURE.md`](REPOSITORY_STRUCTURE.md) — целевая структура Git и правила выделения самостоятельных продуктов.
6. [`LANGUAGE_POLICY.md`](LANGUAGE_POLICY.md) — русский как основной язык и правила использования английской терминологии.

При конфликте базовых документов приоритет имеет `PROJECT_CHARTER.md` до явного исправления противоречия.

## Текущий статус

VEQTA проходит переход от концепции одного prototype-приложения к открытой инженерной и продуктовой экосистеме.

Сейчас уже существуют три реальные группы активов:

```text
Engineering → Frappe Architecture Standard
Learn       → новый архитектурный практикум Frappe
Labs        → Work Management prototype v0.1
Products    → готовых продуктов пока нет
```

Отсутствие готового продукта на текущем этапе является явным статусом, а не пробелом, который нужно закрыть искусственно. Кандидат должен пройти продуктовую и инженерную проверку.

## Для кого VEQTA

Зонтичный бренд VEQTA ориентирован прежде всего на тех, кто создаёт решения на Frappe:

- разработчиков Frappe;
- будущих разработчиков Frappe;
- архитекторов программных решений;
- технических руководителей;
- команды внедрения;
- независимых разработчиков;
- участников open-source проектов.

У каждого будущего Product будет собственная пользовательская аудитория и собственное ценностное предложение.

## Open source

VEQTA развивается как open-source-first инициатива. Базовая стратегическая модель не предполагает искусственного open-core, в котором существенные продуктовые возможности намеренно остаются только в закрытой редакции.

Точный режим лицензирования будет разделён по типам артефактов: software, инженерная документация, учебные материалы и trademarks требуют разных правил. До принятия отдельной лицензионной политики действует существующий файл [`LICENSE`](LICENSE).

Frappe Framework является отдельным upstream-проектом и зависимостью VEQTA.
