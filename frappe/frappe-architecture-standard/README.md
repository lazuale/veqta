# Архитектурный стандарт Frappe

Этот раздел VEQTA Engineering посвящён проектированию приложений на **Frappe Framework v16**.

Его задача — помочь выбрать решение, которое соответствует устройству самого Framework: понять, какая ответственность уже принадлежит Frappe, где достаточно штатного механизма и когда действительно нужен собственный код.

Стандарт не является официальной документацией Frappe Technologies. Существенные утверждения опираются на официальную документацию и исходный код нужной версии. Собственные выводы VEQTA отделяются от фактов Frappe и объясняются рядом с соответствующим механизмом.

## Как читать

Если Frappe только начинает складываться в единую картину, удобнее идти по порядку: от границ Framework и модели данных к жизненному циклу, безопасности, чтению данных, транзакциям, интеграциям и поставке приложения. Глава 12 связывает эти механизмы в единый способ выбора решения, а глава 13 показывает тот же подход на типовых задачах.

Если стандарт используется как справочник при разработке, нужную тему можно открывать отдельно. В каждой главе источники приведены рядом с утверждениями, поэтому отдельный реестр доказательств не требуется.

## Основной принцип

Frappe уже предоставляет модель `DocType` / `Document`, permissions, lifecycle, Desk, REST API, background jobs, scheduler, уведомления, отчёты и точки расширения. Поэтому проектирование начинается с существующей ответственности Framework.

```text
требование
    ↓
какая ответственность нужна?
    ↓
какой механизм Frappe уже отвечает за неё?
    ↓
подходит ли его смысл задаче?
    ├── да → используем штатный механизм
    └── нет → ищем подходящую точку расширения
                    ↓
          собственный механизм появляется там,
          где Framework действительно не закрывает задачу
```

Собственный Python, JavaScript, API или frontend сам по себе не является отклонением от Frappe. Важна граница ответственности: новый код добавляет нужное поведение, а не повторяет уже существующую подсистему Framework.

## Терминология

Основной текст написан по-русски. Официальные имена Frappe сохраняются в исходной форме: `DocType`, `Document`, `Workflow`, `User Permission`, `Assignment`, `Workspace`, `Web Form`, hooks, методы API и другие технические обозначения.

## Версия

Материал ориентирован на **Frappe v16**. Места, где поведение зависит от версии Framework, отмечаются рядом с соответствующим правилом.

Практическое применение этих принципов можно пройти в [учебном практикуме Frappe](../frappe-training/README.md).
