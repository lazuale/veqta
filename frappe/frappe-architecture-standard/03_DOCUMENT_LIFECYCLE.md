# 03. Жизненный цикл Document — где должна жить логика

## 1. Controller — владелец поведения своего DocType

**[ДОКУМЕНТАЦИЯ FRAPPE]** `Controller` — Python-класс `DocType`, наследующий `frappe.model.document.Document`.

Источник:

- https://docs.frappe.io/framework/user/en/basics/doctypes/controllers

**[ИСХОДНЫЙ КОД]** `frappe/model/document.py` показывает, что `Document.save()` и `insert()` выполняют проверки прав доступа, проверку данных и методы жизненного цикла.

Источник:

- https://github.com/frappe/frappe/blob/version-16/frappe/model/document.py

Это означает: `Controller` — не случайное место, куда «удобно положить код», а часть официальной модели `Document`.

---

## 2. Главное разделение: удобство интерфейса и гарантия данных

### Client Script

**[ДОКУМЕНТАЦИЯ FRAPPE]** `Client Script` выполняется в браузере и влияет на стандартную форму.

Источник:

- https://docs.frappe.io/framework/user/en/desk/scripting/client-script

Подходящие задачи:

```text
показать предупреждение;
скрыть или показать поле;
автоматически заполнить удобное значение;
изменить фильтр Link;
добавить кнопку;
немедленно подсказать ошибку пользователю.
```

### Серверная логика Document

Подходящие задачи:

```text
данные никогда не должны нарушать правило;
неправильный Document нельзя сохранить через API;
правило должно работать при импорте и фоновой обработке;
бизнес-инвариант не зависит от интерфейса.
```

### Ключевое правило

**[АРХИТЕКТУРНЫЙ ВЫВОД]**

```text
Client Script = удобство интерфейса
серверная проверка = гарантия модели
```

Это следует из прямого предупреждения документации: проверка в `Client Script` применяется только в стандартной браузерной форме.

## 3. Типовой пример

Правило:

```text
end_date не может быть раньше start_date
```

Неполное решение:

```text
Client Script запрещает выбрать неправильную дату
```

Проблема: `Document` может быть создан через REST API, импорт или серверный код.

Надёжное решение:

```text
Controller.validate()
```

и, при желании, та же проверка на форме для ранней обратной связи.

## 4. Основные методы жизненного цикла

**[ДОКУМЕНТАЦИЯ FRAPPE]** API Controller перечисляет методы жизненного цикла `Document`.

Источник:

- https://docs.frappe.io/framework/user/en/basics/doctypes/controllers

Для архитектурного мышления полезна следующая семантика.

### `before_validate`

Подготовить данные перед проверкой.

Пример:

```text
нормализовать введённое значение;
заполнить производное поле, необходимое для validate.
```

### `validate`

Проверить инварианты `Document`.

Пример:

```text
quantity > 0
end_date >= start_date
parent != self
```

### `before_save`

Последняя подготовка перед обычным сохранением.

### `on_update`

Реакция после обновления `Document`.

Нельзя автоматически превращать `on_update` в место для любой тяжёлой интеграции. Внешние эффекты требуют учёта транзакций — см. `06_TRANSACTIONS_ASYNC.md`.

### `before_submit`

Последняя проверка перед переходом в `Submitted`.

### `on_submit`

Реакция на успешный `submit`.

### `before_cancel`

Проверить, допустима ли отмена.

### `on_cancel`

Реакция на `cancel`.

### `before_update_after_submit` / `on_update_after_submit`

Отдельные методы для разрешённых изменений `Submitted Document`.

## 5. Инвариант должен находиться там, где его нельзя обойти

Инвариант — правило, которое должно быть истинно всегда.

Пример:

```text
Inspection нельзя завершить без result.
```

Если правило реализовано только:

- кнопкой;
- клиентской проверкой;
- скрытием поля;
- фильтром формы,

оно не является гарантией данных.

**[АРХИТЕКТУРНЫЙ ВЫВОД]** Критические инварианты должны проверяться на серверном пути, через который проходят обычные изменения `Document`.

## 6. Server Script — официальный, но особый механизм

**[ДОКУМЕНТАЦИЯ FRAPPE]** `Server Script` позволяет выполнять Python-логику на событии `Document` или как API.

Источник:

- https://docs.frappe.io/framework/user/en/desk/scripting/server-script

Но начиная с v15 `Server Script` **отключён по умолчанию** на общих benches из соображений безопасности; общедоступные shared benches Frappe Cloud его не разрешают.

Отсюда важный вывод.

**[АРХИТЕКТУРНЫЙ ВЫВОД]** `Server Script` не является обязательной промежуточной ступенью между настройкой и Python-кодом приложения.

### Когда Server Script уместен

- автоматизация конкретного сайта;
- ограниченная low-code-настройка;
- логика действительно должна жить как конфигурация сайта;
- среда развёртывания разрешает `Server Script`.

### Когда Controller лучше

- логика является обязательной частью устанавливаемого приложения;
- нужен Git history;
- нужны обычные code review и тесты;
- логика должна одинаково разворачиваться на нескольких сайтах.

## 7. Бизнес-статус, Workflow и docstatus

Это три разных понятия, которые могут взаимодействовать.

### Бизнес-статус

Отвечает:

> Что сейчас происходит с объектом?

Пример:

```text
New
In Progress
Waiting
Done
```

Обычно выражается обычным полем.

### Workflow

Отвечает:

> Какие переходы между состояниями разрешены, кому и при каких условиях?

`Workflow` имеет состояния, переходы, роли и условия.

Официальная документация Workflow:

- https://docs.frappe.io/erpnext/user/manual/en/workflows

### `docstatus`

**[ДОКУМЕНТАЦИЯ FRAPPE]** Системный транзакционный жизненный цикл:

```text
0 Draft
1 Submitted
2 Cancelled
```

Источник:

- https://docs.frappe.io/framework/doctypes/docstatus

`docstatus` отвечает не на вопрос «в какой колонке Kanban находится задача», а на вопрос о системном состоянии транзакционного `Document`.
