# Что создаётся в CORE-практикуме

Практикум строится вокруг небольшого сервиса проката оборудования. Предметная область специально ограничена: она достаточно проста для первого приложения и при этом позволяет пройти основные архитектурные границы Frappe.

## Модель

```text
Equipment
Customer
Rental
└── Rental Item
```

### Equipment

Самостоятельный объект оборудования.

Основные данные:

```text
equipment_name
equipment_type
serial_number
```

`Equipment` получает собственный стабильный `name`, а человекочитаемое название используется как `Title Field`.

### Customer

Самостоятельный клиент, который может участвовать во многих Rentals.

### Rental

Главный рабочий `Document` практикума. Он связывает клиента, период проката, набор оборудования и текущее предметное состояние.

```text
customer
start_date
end_date
status
items
```

Состояния:

```text
Planned
Active
Returned
```

### Rental Item

Child DocType, связывающий Rental с выбранным Equipment.

## Правила приложения

К концу CORE приложение проверяет три предметных инварианта:

```text
V01  end_date не раньше start_date
V02  одно Equipment не повторяется внутри одного Rental
V03  одно Equipment не может одновременно находиться
     в пересекающихся Rentals со статусом Active
```

Проверки выполняются на серверной стороне в логике `Document`, поэтому не зависят от конкретного интерфейса ввода.

## Роли

В практикуме используются две прикладные роли:

```text
Rental Operator
Rental Manager
```

Они позволяют увидеть работу штатных `Role` и DocType Permissions без создания собственной модели доступа.

## Что хранится в App

После прохождения практикума в исходниках `rental_training` находятся:

- Standard DocTypes и их metadata;
- Python controller для Rental;
- роли и необходимая переносимая конфигурация;
- автоматические тесты приложения.

Пользователи и созданные ими Equipment, Customer и Rental остаются данными конкретного `Site`.

## Результат

Финальный этап устанавливает текущее приложение на новый чистый `Site` и проверяет, что модель, права и серверные правила восстанавливаются из App без повторного ручного создания.

Последовательность работы описана в [`PRACTICUM_ROADMAP.md`](PRACTICUM_ROADMAP.md), а исполняемые задания находятся в [`core/`](core/README.md).
