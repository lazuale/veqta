# S02. Решить рабочую выборку через стандартный List View

После S01 оператор видит только свои Rentals, а менеджер — весь набор. Следующее требование не связано с новой бизнес-логикой:

> Пользователю нужно быстро находить Rentals по статусу, клиенту и периоду, сортировать их и возвращаться к рабочей выборке без отдельного интерфейса.

Для такого класса задач Frappe уже предоставляет стандартный `List View`.

На этом этапе не создаются:

```text
Report
Python
SQL
собственная Page
собственный frontend
```

Сначала проверяется штатное представление существующего DocType.

Связанные материалы:

- [`S01_OWNER_PERMISSIONS.md`](S01_OWNER_PERMISSIONS.md);
- [`../APPLICATION_MODEL.md`](../APPLICATION_MODEL.md);
- [`../../../frappe-architecture-standard/09_UI_REPORTING.md`](../../../frappe-architecture-standard/09_UI_REPORTING.md).

## 1. Рабочая задача оператора

Войдите под:

```text
operator-a@example.test
```

Откройте:

```text
Rental → List
```

Нужно получить рабочую выборку:

```text
Status = Active
```

и увидеть только собственные Rentals оператора.

Добавьте фильтр через стандартный интерфейс List.

Результат должен одновременно учитывать две независимые вещи:

```text
List filter
→ выбирает нужное состояние

permissions
→ ограничивает сам набор доступных Documents
```

Фильтр интерфейса не заменяет permissions и не должен показывать записи, которые пользователь вообще не имеет права читать.

---

## 2. Добавить фильтр по Customer

Оставьте или очистите предыдущие фильтры и добавьте условие по:

```text
Customer
```

Выберите одного из Customers контрольного набора.

Проверьте, что список показывает только совпадающие Rentals из уже разрешённого пользователю набора.

Ментальная модель:

```text
permissions
→ определяют доступный набор

List filters
→ помогают работать внутри этого набора
```

---

## 3. Найти Rentals, пересекающие период

Для рабочего реестра часто недостаточно условия вида:

```text
Start Date >= from_date
```

Прокат мог начаться раньше выбранного периода и продолжаться внутри него.

Для периода:

```text
2026-09-01 → 2026-09-10
```

Rental пересекает диапазон, если одновременно выполняется:

```text
Start Date <= 2026-09-10
End Date   >= 2026-09-01
```

Добавьте эти два фильтра в List.

На контрольных данных должны попасть Rentals, которые:

- полностью находятся внутри диапазона;
- начинаются раньше `2026-09-01`, но продолжаются после этой даты;
- заканчиваются после `2026-09-10`, но начинаются не позже неё.

Эта же формула позже будет использоваться в Query Report и Script Report.

---

## 4. Настроить полезные колонки

Для обычной работы с Rental полезно видеть как минимум:

```text
name
customer
start_date
end_date
status
```

Если стандартная настройка текущего List позволяет выбрать отображаемые поля, настройте представление так, чтобы не приходилось открывать Form каждого Rental только ради этих данных.

Не добавляйте новые поля в DocType только для того, чтобы они появились как колонка списка.

Предметная модель уже содержит нужные значения.

---

## 5. Проверить сортировку

Отсортируйте Rentals по:

```text
Start Date
```

а затем по:

```text
End Date
```

Смысл этого шага не в изучении кнопок List View.

Нужно увидеть, что задача:

> найти, отфильтровать и упорядочить рабочие Documents

уже закрывается стандартным представлением Frappe и пока не создаёт ответственности для собственного отчёта.

---

## 6. Сохранить пользовательское представление, если текущий UI это предлагает

Если в используемом Frappe v16 List View доступно сохранение текущего набора фильтров/представления, сохраните рабочий вариант для себя.

Например:

```text
My Active Rentals
```

Такое пользовательское представление является состоянием конкретного Site/User.

Оно не становится обязательной конфигурацией App только потому, что удобно одному пользователю.

Если в вашем patch-release сохранение представления организовано иначе, не создавайте собственный механизм ради точного повторения названия кнопки. Контракт этапа — стандартный List с фильтрами и сортировкой.

---

## 7. Повторить под менеджером

Войдите под:

```text
manager@example.test
```

Откройте тот же `Rental` List и примените фильтр пересечения периода:

```text
Start Date <= 2026-09-10
End Date   >= 2026-09-01
```

Менеджер должен получить подходящие Rentals обоих операторов.

Один и тот же List View работает поверх разных permission boundaries:

```text
Rental Operator
→ только собственные Documents

Rental Manager
→ все разрешённые Documents
```

Для этого не понадобились две разные страницы или два разных DocType.

---

## 8. Где проходит граница List View

Теперь появляется новая задача:

> Менеджеру нужна сохраняемая сводка: сколько Rentals приходится на каждый Status и Customer.

Это уже не просто поиск отдельных Documents.

Нужно:

```text
выбрать поля
сгруппировать строки
посчитать количество записей
сохранить отчётное представление
```

Не нужно сразу писать SQL. Следующий штатный кандидат — `Report Builder`.

---

## 9. Проверить Git

На S02 мы работали только с пользовательским представлением данных.

Проверьте App:

```bash
cd ~/frappe/rental-training-bench
git -C apps/rental_training status --short
```

Не должно появиться изменений только из-за того, что пользователь применял фильтры, сортировку или сохранил персональное представление.

Если появились файлы App, разберите их происхождение до следующего этапа.

## Результат этапа

К концу S02:

```text
обычный реестр решён стандартным List View
permissions продолжают ограничивать доступный набор
фильтры не смешиваются с моделью безопасности
проверена корректная формула пересечения периода
нового кода и новой модели данных не появилось
```

На S03 впервые появляется настоящее требование к отчёту, а вместе с ним — `Report` permission и `Report Builder`.
