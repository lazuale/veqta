# Требования практикума

Практикум начинается не с перечня API чтения и видов отчётов, а с задач уже существующего приложения `rental_training`. Новый механизм Frappe появляется только там, где предыдущего способа решения уже недостаточно.

| Требование | Что появляется | Этап |
|---|---|---|
| Практикум должен начинаться с воспроизводимого состояния завершённого `rental_training` и контролируемых данных нескольких пользователей | проверка исходного App/Site и учебные Site-owned данные | S00 |
| Оператор должен видеть и изменять только созданные им Rental, а менеджер — все Rental | `If Owner` в Standard DocType Permissions для `Rental Operator` | S01 |
| Пользователю нужно находить рабочие Rental по статусу, клиенту и датам без разработки отдельного интерфейса | стандартный `List View` и filters | S02 |
| Менеджеру нужна простая сохраняемая сводка по Rental с колонками, фильтрами, группировкой и агрегатами | `Report` permission для `Rental Manager` и `Report Builder` | S03 |
| Серверное чтение в пользовательском контексте должно сохранять ту же границу доступа, что Desk | `get_list`, явная проверка `read` для одного `Document`; сравнение с доверенным `get_all` | S04 |
| Менеджеру нужен отчёт по использованию Equipment в Rentals за выбранный период, одна строка на связь Equipment ↔ Rental | Standard `Query Report` с параметризованным SQL | S05 |
| Отчёт по всем Rentals не должен становиться доступным оператору, ограниченному своими Documents | роли Standard Report и `Rental Manager` как разрешённая аудитория | S05 |
| Менеджеру нужен показатель занятости Equipment, который требует обработки пересекающихся календарных интервалов | Standard `Script Report` и Python-расчёт | S06 |
| Первая корректная реализация расчёта должна дать измеримый baseline количества SQL-запросов | `Recorder`, SQL capture и `EXPLAIN` | S07 |
| N+1 при подготовке данных отчёта нужно убрать без изменения результата расчёта | set-based выборка через `frappe.qb` / Query Builder | S08 |
| Permission boundary, отчётные расчёты и обязательная конфигурация должны проверяться повторяемо | автоматические тесты | S09 |
| Новый Site должен получить permissions и Standard Reports из App, но не учебных пользователей, Rentals и персональные сохранённые отчёты | поставка состояния App, `migrate` и clean-install проверка | S10 |

Без отдельного требования практикум не добавляет raw SQL вне Query Report, cache, индекс, Prepared Report, background jobs, scheduler, REST API, Webhook, realtime, собственный frontend или новую модель прав доступа.

Модель и смысл расчётов описаны в [`APPLICATION_MODEL.md`](APPLICATION_MODEL.md), последовательность работы — в [`ROADMAP.md`](ROADMAP.md).
