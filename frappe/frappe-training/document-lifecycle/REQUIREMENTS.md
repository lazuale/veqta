# Требования учебного приложения

Практикум начинается не с перечня возможностей Frappe, а с требований к одной внутренней заявке `Purchase Request`. По мере появления новых требований становятся нужны разные механизмы Framework.

| Требование | Что появляется | Этап |
|---|---|---|
| Для второго практикума нужна отдельная учебная граница | `purchase_lifecycle_training` и отдельный Site | S00 |
| Пользователь создаёт внутреннюю заявку с темой, суммой, датой и текущим состоянием | Standard DocType `Purchase Request` и обычный `status` | S01 |
| Заявитель и согласующий имеют разные возможности работы с заявкой | `Role` и DocType Permissions | S02 |
| Состояние заявки должно меняться только по разрешённым переходам | `Workflow` на существующем поле `status` | S03 |
| Отклонённую заявку можно исправить и повторно отправить | `Reject` и повторный `PLT Submit for Review` | S03 |
| Пользователь с двумя ролями не может одобрить собственную заявку | `Allow Self Approval` | S04 |
| Для суммы больше `1000` нужен второй уровень согласования | `PLT Senior Approver` и условия `Workflow Transition` | S05 |
| Окончательно согласованная заявка должна стать Submitted Document | `Is Submittable`, `Submit`, `docstatus = 1` | S06 |
| Согласованную заявку можно официально отменить без удаления | `Cancel` и `docstatus = 2` | S07A |
| Заявитель может создать новую версию отменённой заявки | `Amend` и `amended_from` | S07B |
| Обязательный Workflow должен устанавливаться вместе с App | Standard metadata и filtered fixtures | S08 |
| Пользователи и рабочие заявки не должны становиться конфигурацией App | разделение состояния App и данных Site | S08 |
| Критические правила процесса должны проверяться повторяемо | `IntegrationTestCase` и `apply_workflow()` | S09 |
| Новый Site должен получить готовый процесс без ручного восстановления | чистая установка, `migrate` и проверка результата | S10 |

Без отдельного требования практикум не добавляет Assignment, Notification, REST API, Webhook, background jobs, scheduler, custom frontend, внешние интеграции, динамическую матрицу согласования или настраиваемый лимит.

Подробная реализация каждого требования находится в соответствующем этапе [`stages/`](stages/README.md).
