# Этапы практикума

Практикум проходится последовательно. Каждый этап использует состояние предыдущего.

1. **[S00 — исходное состояние и контрольные данные](S00_BASELINE_AND_DATA.md)**  
   Проверить `rental_training` и подготовить отдельные Rentals для безопасных транзакционных экспериментов.

2. **[S01 — Equipment Movement](S01_EQUIPMENT_MOVEMENT.md)**  
   Добавить самостоятельный журнал фактической выдачи и возврата Equipment.

3. **[S02 — атомарная команда Issue](S02_ISSUE_COMMAND.md)**  
   Сделать явную серверную команду `issue()` и связать изменение Rental с созданием полного набора Movement.

4. **[S03 — автоматический rollback](S03_ROLLBACK.md)**  
   Намеренно оборвать Issue посередине и проверить, что необработанная ошибка откатывает все записи request.

5. **[S04 — ручной commit ломает атомарность](S04_MANUAL_COMMIT.md)**  
   Временно добавить `frappe.db.commit()` и увидеть частично сохранённое состояние.

6. **[S05 — пойманное исключение](S05_CAUGHT_EXCEPTION.md)**  
   Проверить, почему проглоченная ошибка больше не даёт Framework автоматически определить необходимость rollback.

7. **[S06 — атомарная команда Return](S06_RETURN_COMMAND.md)**  
   Добавить зеркальную операцию возврата без новой транзакционной инфраструктуры.

8. **[S07 — Document API и прямой DB update](S07_DOCUMENT_VS_DB.md)**  
   Увидеть, как `frappe.db.set_value` обходит обычный `Document` lifecycle.

9. **[S08 — автоматические проверки](S08_AUTOMATED_TESTS.md)**  
   Закрепить собственные permission и business-operation контракты приложения.

10. **[S09 — поставка состояния App](S09_APP_STATE_DELIVERY.md)**  
    Разделить обязательную модель приложения и рабочие данные Site.

11. **[S10 — чистая установка](S10_CLEAN_INSTALL.md)**  
    Проверить итоговый `rental_training` на новом Site.
