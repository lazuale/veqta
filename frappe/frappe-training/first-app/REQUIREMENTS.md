# Требования учебного приложения

Практикум начинается не с перечня возможностей Frappe, а с требований к небольшому сервису проката. По мере появления требований становятся нужны разные механизмы Framework.

| Требование | Что появляется | Этап |
|---|---|---|
| Нужна отдельная среда для обучения | Bench и чистый Site | S00 |
| Код приложения существует независимо от Site | собственный Frappe `App` | S01 |
| Оборудование существует самостоятельно | `Equipment` как Standard DocType | S02 |
| Клиент существует самостоятельно | `Customer` как Standard DocType | S03 |
| Прокат связывает клиента и несколько единиц оборудования | `Rental`, `Link`, Child DocType, `Table MultiSelect` | S04 |
| У проката есть текущее предметное состояние | поле `status` | S05A |
| Пользователь проходит обычный рабочий сценарий | стандартный Desk | S05B |
| Дата окончания не может быть раньше даты начала | серверная проверка в `Document Controller` | S05C |
| Equipment не повторяется внутри одного Rental | серверная проверка в `Document Controller` | S05C |
| Оператор и менеджер имеют разные права | `Role` и DocType Permissions | S05D |
| Active Rentals одного Equipment не пересекаются | междокументная серверная проверка | S06 |
| Критические правила проверяются повторяемо | автоматические тесты | S07 |
| Состояние приложения переносится между Sites | метаданные и код App | S08 |
| Новый Site получает рабочее приложение из репозитория | чистая установка и проверка результата | S09 |

Подробная реализация каждого требования находится в соответствующем этапе [`stages/`](stages/README.md).
