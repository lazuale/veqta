# Переход на русские статусы `Work Item`

Этот документ нужен только для Site, где `Work Item` уже был настроен по предыдущей конфигурации и содержит документы со значениями:

```text
Open
Waiting
Closed
Cancelled
```

На новом чистом Site миграция не требуется: используйте [Руководство по настройке](setup-guide.md).

Русификация меняет фактические значения `Work Item.status` на:

```text
Открыто
Ожидание
Закрыто
Отменено
```

Простая замена Options в DocType без переноса существующих данных недопустима: старые документы сохранят английские значения и перестанут соответствовать новой конфигурации фильтров и Kanban.

## 1. Сделайте резервную копию Site

Перед изменением значений существующих документов создайте штатную резервную копию Site.

## 2. Временно разрешите старые и новые значения

В `Work Item.status` временно задайте Options:

```text
Open
Waiting
Closed
Cancelled
Открыто
Ожидание
Закрыто
Отменено
```

На этом этапе оставьте Default прежним — `Open`.

Сохраните DocType.

Так старые документы остаются валидными, а Bulk Edit уже может записывать новые русские значения.

## 3. Перенесите существующие документы

В List View `Work Item` последовательно обработайте четыре старых состояния.

| Старое значение | Новое значение |
| --- | --- |
| `Open` | `Открыто` |
| `Waiting` | `Ожидание` |
| `Closed` | `Закрыто` |
| `Cancelled` | `Отменено` |

Для каждого значения:

1. отфильтруйте список по старому `status`;
2. выберите найденные документы;
3. используйте штатный `Bulk Edit` / действие `Edit` в List View;
4. поле — `status`;
5. установите соответствующее русское значение;
6. повторяйте по страницам или партиям, пока фильтр по старому значению не вернёт ни одного документа.

Не удаляйте старое значение из Options, пока хотя бы один документ его использует.

## 4. Проверьте остатки

По очереди проверьте фильтры:

```text
status = Open
status = Waiting
status = Closed
status = Cancelled
```

Каждый должен возвращать ноль документов.

## 5. Зафиксируйте финальные Options

После переноса всех документов замените Options на окончательный набор:

```text
Открыто
Ожидание
Закрыто
Отменено
```

Установите:

```text
Default: Открыто
```

Сохраните DocType.

## 6. Обновите пользовательскую конфигурацию

После миграции данных приведите Site к текущему [Руководству по настройке](setup-guide.md):

- глобальные Saved Filters используют русские статусы;
- Kanban Board называется `Работы` и содержит колонки `Открыто / Ожидание / Закрыто / Отменено`;
- Number Cards и Dashboard Charts фильтруют по русским значениям;
- Calendar View, Workspace и shortcuts получают текущие русские названия;
- записи `Translation` добавляются для `Work Item` и `Low / Medium / High`.

Если на Site уже существуют старые Saved Filters, Kanban Board, Number Cards, Dashboard Charts или Workspace с английскими именами, их нужно обновить или удалить после создания русских вариантов, чтобы не оставлять дублирующий интерфейс.

Значения `priority` не мигрируются. В данных они остаются:

```text
Low
Medium
High
```

и только отображаются по-русски через `Translation` с контекстом `Work Item`.

## Почему миграция нужна

В штатном Kanban Frappe перенос карточки записывает имя целевой колонки непосредственно в поле документа. Поэтому русские Kanban-колонки требуют русских фактических значений `status`, а не только переводов интерфейса.

Для массового изменения документов используется штатный List View Bulk Edit; собственного скрипта или patch для этой миграции не требуется.
