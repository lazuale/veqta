# VEQTA — текущие решения

Этот файл отвечает на вопрос: **что уже решили и почему не нужно заново спорить об этом перед каждым следующим шагом**.

Здесь нет списка будущих функций. Только правила, которые действуют прямо сейчас.

## Платформа

VEQTA разрабатывается как отдельное приложение на **Frappe Framework**.

Что принято:

- ERPNext не является обязательной зависимостью;
- текущая целевая линия — stable Frappe v16;
- возможности Frappe проверяются по официальной документации и исходникам используемой версии;
- собственный механизм не добавляется до подтверждённого ограничения штатного Frappe.

Зачем: Frappe уже даёт DocType, Workflow, permissions, Desk, Assignment, Timeline и другие базовые механизмы. VEQTA не должна писать их второй раз без доказанной причины.

## Данные

Для текущей модели действуют правила:

- один бизнес-факт имеет один источник истины;
- значимые данные имеют явный тип и семантику;
- произвольный JSON/EAV не используется как основа Core;
- производные показатели не хранятся как первичные факты без необходимости;
- история, необходимая для анализа lifecycle, должна быть машинно читаемой;
- изменяемое отображаемое название не используется как единственный машинный идентификатор там, где нужна стабильная ссылка.

Зачем: процесс можно менять, но данные после этих изменений должны оставаться понятными, связанными и пригодными для анализа.

## Prototype v0.1

Сейчас проверяется только:

- `Work Type`;
- `Work Item`;
- Workflow / Workflow State;
- Assign To / `ToDo`;
- Version / Timeline / Workflow comments;
- базовый Desk UI;
- Kanban;
- воспроизводимость конфигурации из Git.

Это граница текущего эксперимента, а не перечень возможностей готовой VEQTA.

Модель: `MODEL_V0_1.md`. Испытания: `PROTOTYPE_V0_1.md`. Прогресс: Issue #2.
